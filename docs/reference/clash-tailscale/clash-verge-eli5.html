像给五岁小孩讲：
Clash Verge 和 Tailscale 怎么一起玩

为什么 ssh mac-mini 会收到一个奇怪的 “403”，又是怎么修好的。

1. 故事里的角色

把你的电脑想成一座房子，每个网络请求都是一封要寄出去的信。

🧑‍✈️ Clash：门口的分拣员
每封信出门前都要经过他。他看一张说明卡（YAML），决定这封信是自己走路送（直连），还是交给快递公司（代理节点）。
🚇 Tailscale：一条秘密地道
从你家直通奶奶家（Mac mini）。门牌号都长成 100.x.x.x 的样子。只有走这条地道才能到奶奶家。
🗺️ 路由表：小区地图
电脑出门先看地图：“去这个门牌号，走哪条路？”地图上写得越具体的路，越优先。
📜 YAML：一张张说明卡
分拣员的工作手册。好几张卡叠在一起，最后合成一张贴在冰箱上的最终卡。

2. 说明卡是怎么叠起来的（YAML 的原理）

分拣员从来不直接看你写的那些卡。每次你按「使用」，Clash Verge 就像做手工一样把卡一层层叠起来，抄出一张最终卡 clash-verge.yaml，贴到冰箱上。分拣员只看冰箱上那张。

三条记住就够：
  1. 别在订阅原卡上写字，它每天会被快递公司换成新的，你写的会消失。
  2. 想改什么就贴贴纸：规则贴在「编辑规则」，其他设置贴在 Merge。
  3. 想知道到底生效没有，只看冰箱上的最终卡 clash-verge.yaml。

小陷阱：老版本的贴纸写法 prepend-rules 写在 Merge 里，新版（2.5.6）已经不认了，会被原样抄到最终卡上，但分拣员不看那一栏。规则要贴在「编辑规则」那张专门的贴纸上。

3. 那个 403 是怎么来的

你想寄信给奶奶家 100.124.189.67。那天秘密地道（Tailscale）正好关着。

SSH 等的是奶奶说“你好”，结果收到的是快递公司的一张退件单（HTTP/1.1 403 Forbidden）。它看不懂，就直接挂断了。

4. 怎么修好的：三道保险

先把地道打开（tailscale up），然后加了三道保险，以后分拣员就不会再碰 100.x 的信：

保险像什么写在哪状态
① 路线排除
route-exclude-address		 在地图上把 100.x 那一片划掉，分拣员那条路压根不经过这里 全局 Merge.yaml 的 tun: ✅ 已生效（主力）
② 分拣规则
IP-CIDR,100.64.0.0/10,DIRECT		 在分拣员手册第一页写：“万一看到 100.x 的信，自己走路送，别给快递” 订阅「编辑规则」的 prepend ✅ 已生效
③ 系统代理跳过
skip-proxy		 另一扇门（系统代理）的门卫名单 订阅原卡自带 ✅ 本来就有

5. 为什么“把 100.64 加进 rules”会有帮助，以及为什么它不是主力

100.64.0.0/10 是什么？ 它是一大片门牌号，从 100.64.0.0 到 100.127.255.255。Tailscale 给每台设备发的门牌号都在这片里（你的电脑是 100.84.96.15，奶奶家是 100.124.189.67）。所以“这一片都别碰”就等于“Tailscale 的东西都别碰”。

加进 rules（分拣规则）有什么用？ 信已经到了分拣员手里时，他会翻手册，翻到第一页看到“100.x 自己走路送”，就不会再交给快递公司，403 也就没了。

但它只是第二道保险：

  • 分拣员只在“按手册干活”（mode: rule）时才翻手册。要是切到“全部交给快递”（mode: global），手册就被跳过了。
  • 信在他手里转了一圈才出门，多绕了一步。

路线排除（第 ① 道）是在地图上就把这片划掉，信从一开始就不经过分拣员。不管他用什么模式都管用，所以它才是主力。两道一起上最稳。

6. 一句话总结

🧑‍✈️ Clash 是门口的分拣员，📜 YAML 是一叠说明卡，按「使用」才会合成一张新的最终卡。
🚇 Tailscale 是去奶奶家的秘密地道，门牌号都是 100.x。
🗺️ 在地图上把 100.64.0.0/10 划出分拣员的地盘（主力），再在手册第一页写“100.x 直送”（备份）。
这样去奶奶家的信永远走地道，再也不会被快递公司 “403” 退回来。
