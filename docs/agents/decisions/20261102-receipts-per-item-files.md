# 2026-11-02: Receipts and their evidence are one file per id

- **Decided:** 2026-11-02, by the user: 「Per-item files (Recommended)」, for "Each receipt id gets its own file, e.g.
  .claude/tdd-guardian/receipts/<ID>.json. The red-receipt.mjs entry builds the vendored engine's receipts.json view at
  run time. The landing gate is unchanged, PRs stop conflicting, and diffs shrink to a few lines. A High-tier tooling PR
  on scripts/tdd, recorded as a decision-log entry."
- **Decision:** Each receipt is tracked as `.claude/tdd-guardian/receipts/<ID>.json` and its evidence entry as
  `.claude/tdd-guardian/receipt-evidence/<ID>.json`, each the object as `JSON.stringify(value, null, 2)` plus a newline;
  the 1,020 receipts and 123 evidence entries at `22ffe5ea` move by `node scripts/tdd/receipt-store.mjs migrate`.
  `receipts.json` is a gitignored view the entry builds for the vendored engine's `record` and writes back from, and
  `evidence.json` is retired. The landing verifier's "keeps every record of the parent" check becomes
  `node scripts/tdd/receipt-store.mjs keep-check --parent <P> --head <H>`: a parent item file deleted or changed at the
  head fails it, and the check is stricter than today's record compare (blob identity, case-insensitive duplicates and
  file shape). The receipt verdict stays a landing condition; the vendored engine is unchanged. ADR-0145 d6's repo-wide
  evidence lock is kept; it now guards per-id files.
- **costs:**
  1. G21: a foreign write to the view made while the entry's own engine call is dead is lost when the next `record`
     rebuilds the view (accepted, R-b).
  2. L3′: a RED whose entry is killed between the engine's save and the write-back is not kept.
  3. keep-check is stricter than today: byte identity, case duplicates and shape. A reformatted parent file fails it.
  4. Two `record`s in one worktree serialise on the store lock.
  5. About 1,020 small blobs replace one file.
  6. A direct `receipt.js` or plugin-hook write to the **same id** during the entry's own live call is overwritten
     without notice. It is outside the protection; rule 10 already calls direct `receipt.js` unsupported (gpt M3).
  A branch cut before the migration also takes one modify/delete conflict and one `migrate --import <tip>`.
