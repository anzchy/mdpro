## Context

The 0.3.5 → 0.3.6 canary left two ready processes, duplicate initial windows and migrations, and an MCP bind conflict. Pinned `tauri-plugin-single-instance` 2.5.2 allows failed connect → unconditional unlink → asynchronous bind; bind failure still permits launch. Tauri restart spawns its replacement before parent exit, so the owner must retire before the spawn. The second spawn's origin remains unproved. See the durable [probe](../test/20261103-d354-probe.md), [diagnosis](../reference/20261103-d354-diagnosis.md) and [path ruling](../reference/20261103-d354-path-ruling.md). Source citations below use `SI` = pinned `tauri-plugin-single-instance-2.5.2/src/`; exact source paths and hashes are in the ruling.

## Options considered

1. **Pre-Builder lock, unchanged macOS plugin.** This excludes cooperating fixed-versus-fixed starts, but loses: private failed-notify unlink and Exit cleanup can remove another listener, and asynchronous bind failure still launches normally (`SI/platform_impl/macos.rs:26–35,48–58,74–75,100–101,124–128`). The public API cannot intercept those steps (`SI/lib.rs:26–28,88–133`).
2. **mdpro-owned macOS admission/listener.** Chosen: synchronous ownership/bind before side effects, bounded forwarding and generation-owned cleanup, with the old wire (`SI/platform_impl/macos.rs:78–92,103–111`; argv[0] at `SI/lib.rs:41–43`).
3. **Reviewed plugin patch.** Loses: it can fix fixed-version ownership, but the current API lacks an early admission/supplied-listener/cleanup hook (`SI/lib.rs:69–72,88–133`); a generic patch adds platform and upgrade maintenance while retaining the legacy limits. No newer-upstream-fix claim is made.
4. **Bind-only election, preflight or sender-only repair.** Loses: bind-only cannot safely reclaim a stale shared path; preflight has a check/use gap; old senders bypass sender fixes. These are design limits, while `SI/platform_impl/macos.rs:61–75,100–128` supplies the concrete stale-path/bind example. A native broker enlarges the lifecycle contract.

## Decision

- **Order and platform.** On macOS: `verify_run::enforce()` validation (silent/read-only) → admission and synchronous private bind → `app.launch` with actionId and safe pid/ppid → draft migration → Builder → setup/publication. Refusal stops before migration, initial-window construction, setup and MCP launch. Keep the lock descriptor close-on-exec and held until actual process exit. Windows/Linux retain plugin registration; move the plugin to a Windows/Linux target-scoped Cargo dependency. Add `security-framework` 3.5.1 as a direct macOS-target-scoped dependency for running-image code-signature validation; its existing `SecCode` wrapper avoids handwritten Security.framework FFI, and this version is already in `Cargo.lock`.
- **Cross-version namespace contract.** Resolve `confstr(_CS_DARWIN_USER_TEMP_DIR)` from the OS, independent of `$HOME`; validate that root as the current UID's private directory, then use `<root>/<configured application identifier>/` (0700), `owner.lock` (stable inode, 0600, never deleted/replaced) and `owner.sock` (0600). Use literal release/verify identifiers, never version, SHA or executable path. Reject an untrusted root, object type, ownership or permissions. The complete socket pathname including its terminating NUL must fit macOS `sun_path[104]`; an overlong path fails admission before side effects, with no alternate root. This location, naming and byte limit are a cross-version contract. ADR-0077's launcher lock remains the cross-run guard for supported verify runs; it permits one active run, so another run refuses before it can forward. ADR-0058's exclusive `instance.json` publication stays first in setup, after admission, and is still a separate guard. Test same-run duplicates and cross-run refusal separately.
- **Restart handover.** Every mdpro-initiated restart goes through Tauri `request_restart` (including the process plugin), never `AppHandle::restart` or direct `process::restart`; a structural test pins the restart call sites. The `RunEvent::Exit` hook is the retirement point because Tauri's direct restart skips that event, and process exit does not reliably run service destructors. At `RunEvent::Exit`, before Tauri's restart spawn, the owner marks itself retiring, stops accepting and closes its listener, drains/rejects pending work, then unlinks only its private `owner.sock` while holding `owner.lock`. It never receives the successor's request. The stable public alias may dangle during this interval. A contender finding the lock held but no live receiver waits and re-contends within one 10-second monotonic startup deadline; Tauri calls `exit(0)` immediately after spawning on macOS, so this allows for scheduling delay beyond its post-spawn work. After the parent exits and releases the lock, exactly one successor acquires and binds. Deadline expiry refuses, never enters setup. Generation-owned cleanup cannot unlink a successor's socket.
- **Legacy compatibility and trust.** The public `/tmp/<normalized-identifier>_si.sock` is compatibility only. A fixed owner creates an alias to its private socket exclusively only if the name is absent; it never overwrites or auto-unlinks an existing public entry. A same-UID public symlink whose target is exactly this namespace's `owner.sock` is mdpro's own alias, not legacy state: the admission lock holder keeps it, recreating it only when the name is absent; it is never classified stale or forwarded to. A contender seeing that alias follows private admission and re-contention. State at that address owned by another UID never blocks private admission: skip the alias, log `compat: foreign_uid`, and do not send it cwd/argv. For a same-UID legacy listener, peer UID alone is insufficient: before sending, require kernel peer PID plus verification of the *running* image's mdpro identity/code signature against an explicit compatible legacy-build allowlist. Unknown, unverifiable or incompatible peers get no request. Test identity qualification independently of UID. A same-UID ambiguous stale or racing legacy entry receives bounded connection retries on ECONNREFUSED, then a visible refusal; failed connect alone never authorizes unlink. Reject proceeding privately while skipping the alias after these retries: a legacy owner can bind after the failed connect and ignores the private lock, recreating duplicate startup effects. Ordinary fixed-owner forwarding uses the same cwd, NUL-NUL, full argv including argv[0], EOF framing, with bounded bytes/time/queue/concurrency. Queue until routing prerequisites exist and preserve `single_instance_args`, file routing and no-file duplicate behavior. No replay after a possibly delivered write; the old wire has no acknowledgement or crash-durable exactly-once promise.
- **Refusal and fallback.** A Finder/GUI refusal shows a native, actionable alert before exit; CLI/launcher refusal writes stderr and exits nonzero. Also log structured Start/Fail with actionId where logging is available; if alert or logging fails, still exit nonzero. For a same-UID stale legacy entry, the recovery text says: verify in Activity Monitor or with `pgrep -fl mdpro` that no mdpro process runs, then remove only the release alias `/tmp/com_mdpro_app_si.sock` and relaunch; if a process remains or ownership is uncertain, quit it or seek support instead. Never instruct removal of a private socket or a different public entry. Probe the exclusive alias, legacy framing, crash/restart recovery, length and foreign-bind races before matrix attack/RED. If the alias or identity proof fails, return this ADR for review before implementation; do not silently drop compatibility or resume unsafe public-path reclamation.
- **Supersession and tooling.** Partially supersede only ADR-0047 decision 4/S4's literal macOS plugin requirement with this admission service; preserve its isolation/order, decision 3, `RunEvent::Opened`, Windows/Linux plugin and control authentication. ADR-0058's structural ordering test and source-version pins must be revised for the macOS service. ADR-0077's launcher lock stays. `scripts/control` doctor/clean/`si.sock` assumptions must be reviewed and updated in the implementation scope: the public address becomes an optional alias, not the authoritative endpoint. ADR-0034's Proposed plugin wording gets a forward pointer if that record is later accepted.

## Consequences

Fixed-version starts gain one admitted application process per identity, without duplicate startup effects; healthy forwarded requests reach the owner once in the ordinary case. Costs: a crashed 0.3.x owner may leave a same-UID public socket, so first upgrade/relaunch can visibly refuse until the targeted recovery above; field frequency is unmeasured, while fixed-only normal use should not hit this path. Unfixed binaries may ignore the lock or remove the public alias. Another UID's address suppresses compatibility only for that launch, not the user's private owner. mdpro maintains macOS IPC, peer identification, queueing, shutdown and tests; upstream behavior may drift. ADR-0058 tests and launcher doctor/clean incur work. No universal mixed-version, arbitrary same-UID mutation or crash-durable delivery guarantee is claimed. Second-spawn provenance and the full released-client update canary remain separate follow-ups.
