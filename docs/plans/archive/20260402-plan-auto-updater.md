## Problem Statement

mdpro has no in-app update mechanism. Users must manually check GitHub releases to
know when a new version is available. The Settings dialog has no "About" page. The
goal: add Settings → About with version info, and a full Tauri updater that downloads
and installs new versions in one click — no browser, no drag-to-Applications.

## What Makes This Cool

Native macOS "Software Update" feel inside an open-source Markdown editor. You open
About, see your version, and if there's something new, one button handles the rest.
No trips to GitHub. No .dmg dragging. The kind of polish that makes daily writers
forget they're using an open-source app.

## Constraints

- Tauri 2.0 + React 19 + TypeScript strict mode
- macOS primary target (ARM64 + Intel), Windows + Linux also built
- No Apple notarization set up yet. On macOS, users may need to right-click → Open
  on each updated build until notarization is configured (Gatekeeper quarantines
  unsigned bundles with an unrecognized hash on every update, not just the first).
  This is a known limitation, not a one-time prompt.
- Settings nav is in `src/components/common/SettingsDialog.tsx` — About page must
  follow the existing `NavItem` pattern
- Signing keys not yet generated — must be generated locally and added to GitHub
  Secrets before first release that uses this feature

## Premises

1. No "About" nav item exists in SettingsDialog today — must be added from scratch.
2. `reqwest` (json feature) is already in Cargo.toml — no new HTTP dependency needed
   for the Rust side.
3. "One-click install" on macOS requires `tauri-plugin-updater`. Auto-downloading a
   .dmg without the plugin is not meaningfully better UX than opening a browser link
   (user still drags to Applications). The plugin is the right path.
4. The Tauri updater needs a `latest.json` hosted on GitHub Releases. This must be
   generated in the CI publish job (not per-build) to avoid race conditions when
   4 platform builds run concurrently. We use a manual shell script (not tauri-action's
   built-in `includeUpdaterJson`) to have full control over the JSON structure and
   avoid the race condition.
5. Single version source of truth: `env!("CARGO_PKG_VERSION")` in Rust (patched by CI).
   The frontend reads it via a Tauri command — NOT from `package.json` via Vite define —
   to guarantee both sides always agree. Eliminates the dual-source drift risk.
6. Apple notarization is deferred. Until it is set up, users may need to right-click →
   Open on each updated build on macOS. This is acceptable for an open-source project
   with a technical-leaning audience. Gate the public announcement on notarization
   being complete if the target audience includes non-technical daily writers.
7. Initial release scopes `latest.json` to macOS only (ARM + Intel). Windows and
   Linux platform entries are added once artifact filenames are confirmed from a
   real CI run. This avoids shipping a broken updater for Windows/Linux users.

## Approaches Considered

### Approach A: Check + Open Browser
```
Summary: Rust command hits GitHub Releases API, returns {current, latest, has_update}.
         About page shows version and a "Download" link that opens the browser.
Effort:  S (~2h with CC)
Risk:    Low
Pros:    Zero new deps. Works today with no CI changes.
Cons:    User still downloads and drags manually. Not "one-click".
Completeness: 6/10
```

### Approach B: Full Tauri Updater (CHOSEN)
```
Summary: tauri-plugin-updater handles background download + in-place install.
         CI generates latest.json. About page shows update state with progress.
Effort:  M (~4h with CC across 8 files)
Risk:    Medium (signing setup required before first use; Gatekeeper caveat on macOS)
Pros:    True one-click install. Industry-standard UX. Upgrade path to notarization.
Cons:    Requires one-time local keygen + 2 GitHub secrets before activation.
Completeness: 9/10
```

## Recommended Approach: B — Full Tauri Updater

### File 6: `src/components/common/settings/AboutSettings.tsx` (new file)

Key design decisions reflected in the code:
- Update handle stored in state (not re-fetched on install — fixes double-request bug)
- Progress tracked via accumulator (not per-chunk — fixes broken progress calculation)
- Explicit `error` phase (network failure shown honestly, not disguised as up-to-date)
- Save guard before relaunch (prevents data loss on dirty documents)
- Result cached for 5 minutes (prevents a new network request on every re-open)
- Version read from Rust via `get_app_version` command (single source of truth)

```tsx
import { useState, useEffect, useRef } from 'react';
import { check, type Update } from '@tauri-apps/plugin-updater';
import { relaunch } from '@tauri-apps/plugin-process';
import { invoke } from '@tauri-apps/api/core';
import { loggingService } from '../../../services/loggingService';
import { useDocumentStore } from '../../../stores/documentStore';

type UpdateState =
  | { phase: 'checking' }
  | { phase: 'up-to-date' }
  | { phase: 'error'; message: string }
  | { phase: 'available'; version: string; body: string | null; handle: Update }
  | { phase: 'downloading'; progress: number }
  | { phase: 'ready' };

// Module-level cache: avoid a network round-trip on every re-open (5 min TTL)
let cachedResult: { state: UpdateState; ts: number } | null = null;
const CACHE_TTL_MS = 5 * 60 * 1000;

export function AboutSettings() {
  const [currentVersion, setCurrentVersion] = useState('...');
  const [state, setState] = useState<UpdateState>({ phase: 'checking' });
  const actionId = useRef(loggingService.generateActionId());

  useEffect(() => {
    void invoke<string>('get_app_version').then((v) => setCurrentVersion('v' + v));
    void runCheck(false);
  }, []);

  async function runCheck(forceRefresh: boolean) {
    const now = Date.now();
    if (!forceRefresh && cachedResult && now - cachedResult.ts < CACHE_TTL_MS) {
      setState(cachedResult.state);
      return;
    }
    setState({ phase: 'checking' });
    loggingService.logEventSync({
      level: 'info', event: 'ui.about.update_check', status: 'start',
      actionId: actionId.current, context: { forceRefresh },
    });
    try {
      const update = await check();
      const next: UpdateState = update
        ? { phase: 'available', version: update.version, body: update.body ?? null, handle: update }
        : { phase: 'up-to-date' };
      cachedResult = { state: next, ts: Date.now() };
      setState(next);
      loggingService.logEventSync({
        level: 'info', event: 'ui.about.update_check', status: 'success',
        actionId: actionId.current, context: { hasUpdate: !!update, version: update?.version },
      });
    } catch (e) {
      const msg = e instanceof Error ? e.message : String(e);
      setState({ phase: 'error', message: msg });
      loggingService.logEventSync({
        level: 'error', event: 'ui.about.update_check', status: 'fail',
        actionId: actionId.current, context: { error: msg },
      });
    }
  }

  async function handleInstall() {
    if (state.phase !== 'available') return;
    const { handle } = state;
    let received = 0;
    let total = 0;
    setState({ phase: 'downloading', progress: 0 });
    await handle.downloadAndInstall((event) => {
      if (event.event === 'Progress') {
        total = event.data.contentLength ?? total;
        received += event.data.chunkLength;
        const pct = total > 0 ? Math.round((received / total) * 100) : 0;
        setState({ phase: 'downloading', progress: pct });
      }
      if (event.event === 'Finished') {
        setState({ phase: 'ready' });
      }
    });
  }

  async function handleRelaunch() {
    // Guard: prompt for unsaved documents before relaunching
    const { documents } = useDocumentStore.getState();
    const dirty = documents.filter((d) => d.isDirty);
    if (dirty.length > 0) {
      const names = dirty.map((d) => d.title || 'Untitled').join(', ');
      const confirmed = window.confirm(
        `You have unsaved changes in: ${names}.\nSave before restarting?`
      );
      if (!confirmed) return;
      // Trigger save-all via existing store action if available
      const { saveAll } = useDocumentStore.getState();
      if (typeof saveAll === 'function') await saveAll();
    }
    await relaunch();
  }

  return (
    <div className="settings-section">
      <h3 className="settings-section-title">About</h3>
      <div className="about-app-info">
        <div className="about-app-name">mdpro</div>
        <div className="about-version">Version {currentVersion}</div>
      </div>
      <div className="about-update-status">
        {state.phase === 'checking' && <span>Checking for updates...</span>}
        {state.phase === 'up-to-date' && <span>✓ You're up to date</span>}
        {state.phase === 'error' && (
          <span className="about-update-error">Could not check for updates. Try again.</span>
        )}
        {state.phase === 'available' && (
          <div className="about-update-available">
            <span>● {state.version} available</span>
            {state.body && <p className="about-release-notes">{state.body}</p>}
            <button className="toolbar-button-primary" onClick={() => void handleInstall()}>
              Install Update
            </button>
          </div>
        )}
        {state.phase === 'downloading' && (
          <span>Downloading... {state.progress}%</span>
        )}
        {state.phase === 'ready' && (
          <div>
            <span>✓ Update ready</span>
            <button className="toolbar-button-primary" onClick={() => void handleRelaunch()}>
              Restart to Apply
            </button>
          </div>
        )}
      </div>
      <button
        className="toolbar-button"
        onClick={() => void runCheck(true)}
        disabled={state.phase === 'checking' || state.phase === 'downloading'}
      >
        Check Again
      </button>
    </div>
  );
}
```

```yaml
- name: Generate and upload latest.json
  env:
    GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  run: |
    VERSION="${{ needs.create-release.outputs.version }}"
    REPO="${{ github.repository }}"
    VERSION_NUM="${VERSION#v}"

    # Download all .sig files
    mkdir -p sigs
    gh release download "$VERSION" --repo "$REPO" --pattern "*.sig" --dir sigs || true

    # Read signatures (macOS only for initial release — Windows/Linux TBD after
    # artifact filenames are confirmed from a real CI run)
    MACOS_ARM_SIG=""
    MACOS_X64_SIG=""
    [ -f "sigs/mdpro_${VERSION_NUM}_aarch64.app.tar.gz.sig" ] && \
      MACOS_ARM_SIG=$(cat "sigs/mdpro_${VERSION_NUM}_aarch64.app.tar.gz.sig")
    [ -f "sigs/mdpro_${VERSION_NUM}_x64.app.tar.gz.sig" ] && \
      MACOS_X64_SIG=$(cat "sigs/mdpro_${VERSION_NUM}_x64.app.tar.gz.sig")

    PUB_DATE=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
    BASE_URL="https://github.com/$REPO/releases/download/$VERSION"

    cat > latest.json << EOF
    {
      "version": "$VERSION",
      "notes": "See release notes at https://github.com/$REPO/releases/tag/$VERSION",
      "pub_date": "$PUB_DATE",
      "platforms": {
        "darwin-aarch64": {
          "signature": "$MACOS_ARM_SIG",
          "url": "$BASE_URL/mdpro_${VERSION_NUM}_aarch64.app.tar.gz"
        },
        "darwin-x86_64": {
          "signature": "$MACOS_X64_SIG",
          "url": "$BASE_URL/mdpro_${VERSION_NUM}_x64.app.tar.gz"
        }
      }
    }
    EOF

    gh release upload "$VERSION" latest.json --repo "$REPO" --clobber
    echo "Uploaded latest.json for $VERSION"
```

## Success Criteria

- Settings → About shows current version (`v0.2.x`, matching the git tag, read from Rust)
- On a machine running an old version, About shows "● vX.Y.Z available" within 3s of opening
- "Install Update" downloads and installs without opening a browser or Finder
- "Restart to Apply" prompts for unsaved documents, then relaunches to the new version
- Machines already on latest version show "✓ You're up to date"
- Network failure shows "Could not check for updates. Try again." — not a false up-to-date
- Re-opening About within 5 minutes does not trigger a new network request
- Progress percentage increases monotonically during download

### CODEX SAYS (eng — architecture challenge)

**Finding 1 — CRITICAL: `bundle.createUpdaterArtifacts` missing**
`tauri.conf.json:35` has no `bundle.createUpdaterArtifacts: true`. Without this flag, Tauri never generates `.app.tar.gz` or `.sig` updater assets. The entire update pipeline is inert even after notarization is enabled. Must add `"createUpdaterArtifacts": true` under `bundle` in `tauri.conf.json`.

**Finding 2 — HIGH: Relaunch/save needs app-level coordinator**
The plan's `handleRelaunch` in `AboutSettings.tsx` assumes it can find and save all dirty docs, but `useDocument.ts:168` only saves the active document and `documentStore.ts` has no save-all method. Untitled dirty docs still need interactive Save As (can't be saved without a path). This logic must live in a `prepareForRelaunch()` function in a hook/service — not embedded in a settings panel. The settings panel should call into the coordinator and display results.

**Finding 3 — HIGH: Updater state lost on dialog unmount**
`SettingsDialog.tsx:108` unmounts the About panel when the dialog closes. `SettingsDialog.tsx:158` unmounts it when switching tabs. Module-level cache only partially helps. The `Update` handle in `available` state is an opaque Rust object — if cached across remounts, it may be stale or invalidated. Fix: move all updater lifecycle state into a Zustand store (or app-level hook) that persists across dialog open/close, and either lock the dialog from closing during `downloading`/`ready` or hard-reset state on remount.

**Finding 4 — MEDIUM: CI `latest.json` generation is brittle**
Plan hardcodes `mdpro_aarch64.app.tar.gz` filenames. Real artifact names may differ by platform or version. Use `gh release view $TAG --json assets` to dynamically discover actual asset names and URLs. Also, plan sets `"notes"` to a URL string — the design phase requires actual Markdown content. Fetch release body from GitHub API.

**Finding 5 — MEDIUM: `get_app_version` not codebase-conformant**
All commands in this repo return `Result<T, String>` and log `Start`/`Success`/`Fail` pairs. Plan's `get_app_version` returns a plain `String`. Small fix: return `Result<String, String>`, add logging.

### CLAUDE SUBAGENT (eng — independent review)

**#1 — CRITICAL compile error:** `d.isDirty` doesn't exist on `Document` type (`src/types/document.ts:15,28`). Correct field is `isModified`. TypeScript will reject this at `tsc`.

**#2 — CRITICAL data loss:** `saveAll()` doesn't exist in `documentStore`. The plan's typeof guard silently skips the call and relaunches anyway — all unsaved documents are lost. Fix: iterate `documents`, call `invoke('save_file', ...)` per `isModified` doc. Block relaunch on failure.

**#3 — CRITICAL runtime failure:** `tauri_plugin_process` is not registered in `src-tauri/src/main.rs`. The `relaunch()` call will fail at runtime with a plugin not found error. Must add `.plugin(tauri_plugin_process::init())` and `tauri-plugin-process = "2"` to `Cargo.toml`.

**#4 — CRITICAL capability gap:** `"process:default"` is missing from `src-tauri/capabilities/default.json`. `relaunch()` will also be rejected by Tauri's capability system even if the plugin is registered.

**#5 — HIGH: no error handling on `handleInstall`:** No `try/catch` around `await state.handle.downloadAndInstall()`. A network failure mid-download permanently stalls the state machine in `downloading`. Add `try/catch` → transition to `error` state with message.

**#6 — HIGH: stale Update handle in cache:** Module-level `cachedResult` caches the `available` state including the `Update` handle. On Settings reopen, the cached `available` handle may refer to a Rust object that has since been freed. Safe to cache: `up-to-date` and `error`. Must NOT cache `available` — always re-check on panel open.

**#7 — HIGH: CI race with partial builds:** `release.yml` has `fail-fast: false` on the build matrix. If macOS build fails but Windows succeeds, `publish-release` still runs and generates a `latest.json` with missing or unsigned macOS entry. Add a `check-all-builds` gate job (or `fail-fast: true`) before `publish-release`.

**#8 — HIGH: `endpoints:[]` → misleading error:** When `endpoints` is empty, `check()` throws immediately. The error state shows "Couldn't reach the update server" — factually wrong for intentionally disabled updates. Add `updates-disabled` phase: detect the no-endpoints condition before calling `check()` and show "Automatic updates coming soon."

**#9 — MEDIUM: `Check Again` active in `ready` phase:** User presses "Check Again" after download completes → new `check()` call abandons the downloaded `Update` handle. The ready state is lost. Disable "Check Again" (and "Install Update") once in `ready` phase.

**#10 — MEDIUM: indeterminate progress:** `contentLength` is `null` when server doesn't send `Content-Length` header. In that case `progress` stays `0` and shows "0%" forever. Use `<progress value={n > 0 ? n : undefined} max={100}>` — `value={undefined}` triggers browser-native indeterminate animation.

// prepareForRelaunch() coordinator:
async function prepareForRelaunch(): Promise<boolean> {
  const { documents } = useDocumentStore.getState();
  const modified = documents.filter(d => d.isModified);  // NOT isDirty
  for (const doc of modified) {
    if (!doc.path) {
      // Untitled doc: cannot save without path → block relaunch
      useToastStore.getState().showToast(
        `"${doc.title}" has unsaved changes. Save it before updating.`
      );
      return false;
    }
    try {
      await invoke('save_file', { path: doc.path, content: doc.content, encoding: doc.encoding ?? 'utf-8' });
    } catch (e) {
      useToastStore.getState().showToast(
        `Failed to save "${doc.title}". Update cancelled.`
      );
      return false;
    }
  }
  return true;
}

async function handleInstall() {
  if (state.phase !== 'available') return;
  const handle = state.handle;
  setState({ phase: 'downloading', progress: 0 });
  try {
    await handle.downloadAndInstall((event) => {
      if (event.event === 'Progress' && event.data.contentLength) {
