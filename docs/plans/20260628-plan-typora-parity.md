## Problem Statement

mdpro is positioned as "Typora's WYSIWYG + modern design." A feature audit
(2026-06-28) found the core editing loop solid — dual WYSIWYG/source/split modes,
GFM tables with a real editing UI, image paste/resize, autosave, file watching,
themes, a 10-tab settings panel. But three things keep it visibly *behind* Typora
and make a technical user bounce within minutes:

1. **Rendering is incomplete.** No math/LaTeX, no Mermaid, no footnotes.
2. **Export is HTML-only.** No PDF, no print support.
3. **Editor polish gaps.** No WYSIWYG find/replace, no code-copy button, no word
   count, no slash commands, no custom themes/CSS.

This plan closes the **single-file editor** gap to Typora. The workspace/vault track
lives in the companion plan and is independently sequenced.

**Review restructure (2026-06-28):** the eng review + Codex flagged that the
**sanitizer policy** and **data-loss hardening** are *blockers*, not polish — you
cannot safely inject KaTeX/Mermaid HTML until the sanitizer allow-list is redesigned,
and data-loss tests must not sit behind cosmetic features. They are now **Phase 0**
and land first. The plan stays a single roadmap (decision: keep one file) but every
phase is an independently shippable PR set with hard boundaries.

## Constraints

- Tauri 2.0, React 19, Milkdown 7 (ProseMirror), CodeMirror 6, pulldown-cmark 0.11.
- Files under ~300 lines; follow `.claude/rules/` (logging rule 20, TDD rule 10,
  IPC pattern rule 50, design tokens rules 30–34).
- Keyboard shortcuts stay in sync across 3 files (menu.rs, preferences, docs) per rule 41.
- Plugin CSS co-located with the plugin, never global (rule 50 §4).
- Local-only, no cloud. HTML/PDF export must render fully offline (bundle KaTeX; Mermaid
  pre-rendered to SVG at export time — see WI-1.2 / WI-2.1).

## Premises (review-revised)

- **P1 — pulldown-cmark carries the parser work.** 0.11 exposes `Options::ENABLE_MATH`
  and `ENABLE_FOOTNOTES`; `markdown.rs:330-335` already toggles tables/tasklists the
  same way. Additive flags + a render hook, not a new parser. *Caveat (Codex): footnote
  back-links and math wrappers need an explicit event-rewrite, not just the flag.*
- **P2 — Math/Mermaid render client-side in preview/WYSIWYG, pre-rendered for export.**
  KaTeX typesets math; Mermaid renders diagrams. Both fail soft (raw source + error
  badge, never blank/crash). For **export/PDF**, Mermaid is pre-rendered to inline SVG
  and KaTeX CSS is inlined — exported files run with zero JS.
- **P3 — PDF export = WKWebView native print-to-PDF** (review decision). No headless
  Chromium bundle. Reuses the themed export HTML. **Spike required first** (Codex): the
  current `export.rs:41` only does `rfd` + `fs::write`; confirm the WKWebView print path
  produces acceptable page breaks before sizing WI-2.1 firmly.
- **P4 — WYSIWYG find/replace is the highest-frequency missing interaction**, but its
  *semantics* must be pinned before implementation (see WI-3.1).

## Architecture — Rendering Consistency (read before Phase 1)

There are **FOUR** render surfaces, not three (Codex correction). Any new syntax
(math, mermaid, footnotes) must be handled — or degrade cleanly — on all four:

```
                          SOURCE OF TRUTH: pulldown-cmark (Rust)
                                      │
        ┌──────────────┬──────────────┼──────────────────┬─────────────────┐
        ▼              ▼              ▼                  ▼                 ▼
  [1] Rust preview  [2] Rust export  [3] JS fallback   [4] Milkdown      (source mode:
  markdown.rs →     html_template.rs marked+DOMPurify  WYSIWYG           CodeMirror —
  sanitize_html →   (export.rs)      exportService.ts  (ProseMirror)     highlight only,
  Preview.tsx       inlines styles   :83 (browser/no-  schema+parser+    no render)
  + KaTeX/Mermaid   + pre-rendered   Tauri fallback)   serializer+
  passes            Mermaid SVG                         nodeview
```

**Consistency strategy (decision A1):**
- pulldown-cmark (Rust) is the **canonical** renderer. Surfaces [2] and [3] must match
  its output for math/footnotes; the JS Marked fallback (`exportService.ts:83`) does NOT
  get math/footnotes for free — it needs the same remark/rehype passes or an explicit
  "fallback does not support math" degradation, tested.
- A **shared golden-fixture suite** (`src/test/render-fixtures/`): a set of
  `markdown → expected-HTML` cases run against surfaces [1], [2], [3], and a
  `markdown → expected-ProseMirror-doc` set against [4]. A new syntax is "done" only
  when it passes on every surface or has a tested degradation.

**Performance (decision P1):** preview re-renders via `dangerouslySetInnerHTML` then a
JS pass (`Preview.tsx:17-22`). Math/Mermaid passes must **memoize per block by source
hash** (render each block once; re-render only changed blocks) and **debounce** the
pass. Naive whole-doc re-render on every keystroke thrashes on diagram-heavy docs.

## Architecture — Sanitizer Policy (read before Phase 0 & Phase 1)

**This is the blocker.** Today the Rust sanitizer preserves a narrow tag/attr set
(`markdown.rs:211`) and the frontend export sanitizer adds only `mark`, `u`,
`data-heading-id` (`exportService.ts:35`). KaTeX output, Mermaid SVG, footnote anchors,
and the `class`/`style`/`aria-*` they need will be **stripped** unless the policy is
redesigned first. Conversely, a too-broad allow-list reopens XSS.

**WI-0.1 redesigns the allow-list explicitly, per feature**, with a single matrix that
both the Rust (`sanitize_html`) and frontend (DOMPurify) surfaces implement identically:

| Feature | Tags added | Attrs added | Risk controlled |
|---|---|---|---|
| Math (KaTeX) | `span`,`math`,`semantics`,`annotation`,`mrow`… | `class` (katex-*) | no `style` with `url()`, no event attrs |
| Footnotes | `sup`,`a`,`section`,`ol`,`li` | `id`,`href`(#-only),`class` | href restricted to in-doc anchors |
| Mermaid | `svg`,`g`,`path`,`text`,`foreignObject`… | `class`,`d`,`viewBox`… | specific SVG profile; strip `<script>`, `on*`, external `href` |
| Custom CSS | n/a (separate path) | n/a | see threat model below |

**Custom-CSS threat model (Codex):** "scoped to editor root" is *not* security. Injected
CSS can hide UI, overlay click targets, and exfiltrate via `url()` background fetches.
WI-3.3 must: strip `@import` and `url(http…)`, forbid `position:fixed` outside the
preview root, and gate behind an explicit "I trust this theme" confirmation.

**Mandatory test (decision A5):** a `<script>`/`onerror`/`url(http…)` payload embedded
in a math expression, a mermaid block, a footnote, and a custom-CSS file is neutralized
on every surface. This test gates Phase 1.

## Phase 0 — Safety foundation (BLOCKERS — land first)

### WI-0.1 — Sanitizer policy redesign — M
- Implement the allow-list matrix above identically in `sanitize_html` (markdown.rs) and
  the frontend DOMPurify config (exportService.ts). Single shared definition of the
  policy (a constant both reference, or Rust-authoritative with the JS mirror tested
  against it).
- **Tests:** the script-injection neutralization suite (math/mermaid/footnote/CSS
  payloads) on all four surfaces; KaTeX/Mermaid/footnote *legitimate* output survives.

### WI-0.2 — Data-loss E2E + logic fallback — M  **[highest data-loss risk]**
- **Now:** cover the unsaved-changes→Quit and external-edit-conflict **logic** via the
  existing Vitest+jsdom fake-IPC pattern (precedent: `useFileWatcher.test.ts`,
  `useAutoSave.test.ts`). Dirty doc + quit → prompt fires, Cancel aborts, Discard
  proceeds; external edit → reload dialog, in-editor unsaved edits not clobbered.
- **Blocked-by:** full WKWebView E2E (real window, real Cmd-Q) requires the harness in
  [`20260610-plan-e2e-verify-skill.md`](./20260610-plan-e2e-verify-skill.md) (APPROVED,
  unbuilt — no `playwright` dep, no `tests/e2e/`). Mark those two cases `[→E2E BLOCKED]`.

### WI-0.3 — Encoding hardening (safety-first) — M
- `encoding.rs` has **zero unit tests**. Add UTF-16/BOM round-trip + CRLF round-trip
  (open CRLF → edit → save preserves CRLF).
- **GBK/Latin-1 (Codex caveat — dangerous if naive):** Latin-1 accepts *any* byte and
  silently masks bad UTF-8. Do NOT add a blind decode. Add: detection **confidence**,
  **persist the detected encoding** per document, and a **save round-trip rule** (save
  back in the original encoding unless the user converts). Tests assert no silent
  corruption, not just "it decoded."

### WI-0.4 — I/O failure paths — S
- Read-only save (EACCES surfaced, not silent), file deleted between open and save
  (stale path), filenames with spaces/emoji/quotes round-trip (macOS NFD).
- Very long single line (minified content) — no editor freeze; large-file (~10MB)
  responsiveness smoke test.

### WI-0.5 — Preferences/launch Rust tests + write-through failure UX — S
- `preferences.rs`, `launch.rs`, `menu.rs` are untested. Add settings-persist-across-
  restart and launch-path coverage.
- **Bundled from TODOS.md (decision Q3):** wrap `preferencesService.setPreferences()`
  in a try/catch and surface a "Failed to save preferences" toast (the write-through
  model currently fails silently on disk error).

## Phase 1 — Rendering completeness

Gated on Phase 0 (sanitizer + the golden-fixture harness). Each WI must pass the shared
4-surface golden suite (see Rendering Consistency section).

### WI-1.1 — Math / LaTeX (`$...$`, `$$...$$`) — M/L
- **Rust:** enable `Options::ENABLE_MATH`; emit `<span class="math-inline">` /
  `<div class="math-display">` carrying raw TeX. (Sanitizer already updated in WI-0.1.)
- **Preview/export:** bundle KaTeX (CSS + fonts, offline); render math post-injection in
  `Preview.tsx` with the memoized per-block pass. Export inlines KaTeX CSS.
- **WYSIWYG (decision A3 — reuse official):** adopt **`@milkdown/plugin-math`** (not in
  deps yet; `package.json` has only `@milkdown/kit` + `@milkdown/react`). Write custom
  code ONLY for the inline-source-reveal on cursor enter that the official plugin lacks
  (mirror `inlineEditPlugin`). *Sizing note (Codex): Milkdown math = schema + parser +
  serializer + nodeview + copy/paste + markdown round-trip — size as L, not M.*
- **Tests:** Rust math→HTML (inline, display, escaped `\$`, math-inside-code-fence does
  NOT render); golden suite all surfaces; WYSIWYG round-trip (type TeX → serialize → same
  markdown); fail-soft on invalid TeX.

### WI-1.2 — Mermaid diagrams — M
- Detect ```mermaid fences. Preview + WYSIWYG render via mermaid.js (bundled).
- **Export strategy (Codex gap):** exported HTML/PDF must run with no JS, so Mermaid is
  **pre-rendered to inline SVG at export time** (run mermaid → serialize SVG → sanitize
  per the SVG profile → inline). Define this in the export pipeline, not just preview.
- **Fail-soft:** invalid diagram → error card with mermaid's parse error + raw source.
- **Tests:** valid → `<svg>`; invalid → error card (not blank); non-mermaid fence
  untouched; **exported HTML contains inline SVG and no `<script>`**; SVG-injection
  payload neutralized (ties WI-0.1).

### WI-1.3 — Footnotes (`[^1]`) — S/M
- Enable `ENABLE_FOOTNOTES`. **Back-links need an explicit event rewrite** (Codex) — the
  default render path does not emit return anchors; implement the ref↔def linking.
- WYSIWYG: Milkdown footnote support, or render-only with a documented limitation.
- **Tests:** single/multiple, undefined reference, ordering, back-link anchors resolve.

### WI-1.4 — Auto-link + emoji — S
- Auto-link bare URLs (pulldown-cmark autolink option). Emoji shortcodes (`:smile:`)
  behind a setting. Document non-support of definition lists / callouts (see NOT in scope).
- **Tests (decision — test gap G1):** auto-link of bare URL; URL inside code fence NOT
  linked; emoji shortcode → glyph; unknown shortcode left literal.

## Phase 3 — Editor polish

### WI-3.1 — Find & replace in WYSIWYG — M
- Reverse the "out of scope" decision in `extensions/search.ts`. **Pin semantics first
  (Codex):** search operates on **rendered text** (what the user sees), match navigation
  highlights in the ProseMirror doc; replace applies to text nodes only — NOT link URLs,
  code-block contents, or math source (those are structural; document the exclusion).
- **Cross-mode parity (decision D2 — RESOLVED: one shared themed bar).** Build a single
  token-themed find/replace bar used by BOTH WYSIWYG and source mode; restyle the
  CodeMirror `@codemirror/search` panel to the same surface rather than shipping the
  WYSIWYG bar themed while source mode keeps the un-themed default (rule-30 cross-mode
  parity; less code long-term). Focus ring rule-33 pattern 1; `aria-live` match count.
- **Tests:** match nav, replace-one, replace-all, regex toggle, no-match, **and the
  exclusion cases** (replace does not corrupt a link URL / code block / math).

### WI-3.2 — Slash command menu (`/`) — M
- ProseMirror `/` block menu reusing the `ImageContextMenu`/`TableContextMenu` +
  `ActionList` contract (ARIA `role="menu"`/`menuitem`, keyboard nav, dismiss, z-1000).
- **Command scope (decision D4 — RESOLVED: ship the full set now).** Ship the full listed
  command set — headings, lists, table, code, math, mermaid, image — in the first cut; the
  reused menu contract makes each item cheap and a half-populated menu reads as unfinished.
- **Tests:** filter-by-query, insert-on-select, escape closes, dismiss on blur,
  "No commands" empty state.

### WI-3.3 — Custom themes / CSS — M
- User CSS from `~/.mdpro/themes/*.css`; expose in Appearance settings.
- **Security (per Sanitizer Policy threat model):** strip `@import` and external `url()`,
  forbid `position:fixed` outside preview root, gate behind a trust confirmation.
- **Trust gate UX (decision D3 — RESOLVED: per-theme one-time confirm).** Gate each custom
  theme behind a one-time "I trust this theme" confirmation using the existing `.dialog-card`
  modal contract (rule 32) — not a single global "allow custom themes" toggle. Matches how
  users reason about trusting one file and the product's file-first posture; persist the
  per-theme grant.
- **Tests:** load/apply/remove; malformed CSS doesn't break the app; `url(http…)` and
  `@import` stripped; a hostile theme cannot overlay the app chrome.

### WI-3.4 — Smaller polish — S
- Resizable sidebar (replace fixed `--sidebar-width: 220px`) — visual QA, no unit test.
- Tab drag-to-reorder in `BottomTabs.tsx`.
- Verify smart-list continue-on-Enter works on nested/ordered lists (audit flagged
  PARTIAL); add a test either way.
- **Bundled from TODOS.md (decision Q3):** clean up ghost shortcuts (`fileNewWindow`,
  `fileOpenQuickly`, `fileSaveAs`, `viewSwitchDocuments`) that appear configurable but
  have no `menu.rs` handler — do it alongside the shortcut-touching work here.
- **Tests (decision — test gap G2):** tab drag-reorder behavior via ARIA (rule 10);
  smart-list continuation.

### WI-3.5 — Spell check decision (split from the grab-bag, decision Q1) — S
- **Decision: delete the dead stub.** `spellCheckPlugin.ts` is a `TODO` stub with no
  highlighting, and the setting is false UI. Remove the plugin + its setting now.
- Leave a TODOS.md entry to add real spell-check (system/hunspell dictionary) later.
- **Tests:** the setting and plugin are gone; no dangling references.

### Pass 3 — Fail-soft journey (the trust spec)

`DESIGN.md` "memorable thing" = *respect the file*. The fail-soft arc must reinforce it:
when render fails, the user must always be **one glance from their raw source** so they
trust nothing was eaten. Concretely: every error state keeps the source recoverable
(inline raw TeX; Mermaid `<details>` source; literal footnote text). No error state may
be a dead-end "⚠ Error" with the content hidden — that erodes the file-first trust the
product is built on.

### Pass 6 — Accessibility + CJK (added; was unspecified)

- **Keyboard:** slash menu inherits the context-menu keymap (Arrow/Home/End/Enter/Esc).
  Find/replace: Cmd-F focuses the field, Enter = next, Shift-Enter = prev, Esc closes and
  returns focus to the editor (rule 33 testing checklist). Trigger `/` only at line/block
  start or after whitespace so it doesn't hijack literal slashes.
- **Focus indicators (rule 33):** find/replace inputs + theme `<select>` use **pattern 1**
  (`border-color: var(--color-accent)` + `box-shadow: 0 0 0 2px var(--color-accent-soft)`).
  Slash-menu items use **pattern 3** (background highlight on the active row). No bare
  `outline:none`. Test both themes (rule 34) — focus on `#2563eb`/white ≠ `#60a5fa`/`#0f1115`.
- **Screen readers:** slash menu `role="menu"`/`menuitem` (free from the reused contract);
  find/replace match count in an `aria-live="polite"` region; error cards readable text,
  not color-only (rule 33 hard rule 5).
- **Contrast (WCAG AA):** danger-on-danger-soft in the error card must clear 4.5:1 for the
  message text in **both** themes — verify, since `*-soft` is a `color-mix` alpha.
- **CJK-aware (DESIGN.md: CJK is first-class):** the word/char count must count CJK
  correctly (a CJK run is N characters, not one "word") — reuse the existing `cjk-slug`
  segmentation logic the plan already cites in WI-2.3; add a CJK fixture to its test.
- **Targets:** desktop pointer; no 44px touch-target rule, but slash-menu rows and the
  find-bar buttons should keep the existing toolbar control sizing for muscle-memory parity.
