## Problem Statement

mdpro is fundamentally a **per-file** editor: you open individual files and edit them.
A feature audit (2026-06-28) found that the entire "workspace" dimension that
Obsidian-class tools own is absent:

- **No folder/vault browser** — you cannot open a directory and navigate a file tree.
  The sidebar is TOC-only (`src/components/Sidebar/index.tsx` is hardcoded to `<TOCSidebar>`).
- **No global search** across files — search is single-document CodeMirror only
  (`extensions/search.ts`).
- **No quick-open / `Cmd-P` fuzzy file finder** — only a 10-item recent list buried in
  the native menu.
- **No `[[wiki-links]]`, backlinks, or graph view** — `[[` is currently escaped/
  sanitized, not parsed.
- **No tags / metadata panel** — YAML frontmatter is stripped for export/TOC but never
  rendered or surfaced.
- **No session restore** — relaunch doesn't reopen the last files.

This plan adds the workspace layer **without breaking the single-file flow**. mdpro
should work exactly as today when you open a lone file, and gain a vault sidebar,
cross-file search, and linked-note navigation when you open a folder. This is a larger,
strategically distinct bet than the parity track — it moves mdpro into Obsidian's
category, not just Typora's.

## Constraints

- Tauri 2.0, React 19, Zustand 4. Local filesystem only (no cloud, no plugin marketplace).
- **Must not regress single-file usage.** Opening one file behaves as today; the vault
  is additive. The sidebar must host *both* the file tree and the existing TOC.
- File watching must scale from one file to a whole tree (current `file_watcher.rs`
  watches open files; a vault watches a directory recursively, debounced).
- Files under ~300 lines; follow `.claude/rules/` (IPC pattern rule 50, Zustand
  conventions rule 50 §1, logging rule 20, TDD rule 10, design tokens 30–34).
- Respect the 10MB per-file cap and existing encoding/line-ending handling.
- Performance: a vault can hold thousands of files — indexing must be incremental and
  off the main thread (Rust side), never block the UI.

## Premises

- **P1 — "Vault" = an opened root folder, persisted in preferences.** No database, no
  proprietary format. The vault is just a directory; mdpro indexes it. This matches the
  "local files only" constraint and Obsidian's own model.
- **P2 — The Rust backend owns the index.** File-tree walk, full-text search, and
  link-graph extraction live in Rust (fast, off-main-thread), exposed via IPC commands
  following the existing 3-layer pattern (rule 50 §2). The frontend renders; it does not
  walk the filesystem.
- **P3 — The sidebar becomes multi-panel.** Today `Sidebar/index.tsx` renders only
  `<TOCSidebar>`. It becomes a switchable/stacked container: **Files**, **Search**,
  **Outline (TOC)**, **Tags** — like Obsidian's left ribbon. TOC is preserved verbatim.
- **P4 — Links are a parser + index concern, reusing the markdown pipeline.** `[[wiki]]`
  and standard `[md](links)` are extracted during indexing; backlinks are the inverse
  index. The graph view is a read-only visualization over that index — built last,
  optional.
- **P5 — Frontmatter is already parsed, just not surfaced.** `yaml-frontmatter` utils
  and `tocService` already read frontmatter. Tags reuse that; no new parser.

## Phase 1 — Vault foundation (the unlock; everything else depends on it)

### WI-1.1 — Open folder as vault — M
- `open_vault` / `read_vault_tree` Tauri commands in a new `commands/vault.rs`: pick a
  directory (rfd), walk it (respect `.gitignore`-style ignores + hidden files toggle),
  return a tree of markdown (and optionally all) files. Register in `commands/mod.rs`.
- `src/stores/vaultStore.ts` (Zustand, rule 50 §1): current vault root, tree, expansion
  state, selected file. Persist vault root in preferences for reopen.
- Typed wrapper `src/services/vaultService.ts`.
- **Tests:** Rust tree walk (nested dirs, ignore rules, non-md files, empty dir,
  permission-denied subdir); `vaultStore` selectors/actions.

### WI-1.2 — File-tree sidebar panel — M
- `src/components/Sidebar/FileTree/` — collapsible tree, click-to-open (reuse existing
  `openFile` flow → adds a tab), active-file highlight, modified indicator.
- Refactor `Sidebar/index.tsx` into a multi-panel host (P3) with a panel switcher;
  preserve `<TOCSidebar>` as the "Outline" panel unchanged.
- Context menu: new file, new folder, rename, delete (with confirm per rule 25),
  reveal in Finder.
- **Tests:** tree render/expand/collapse, open-on-click adds a tab, rename/delete flows
  (component behavior via ARIA, not CSS, per rule 10).

### WI-1.3 — Session & vault restore — S
- On launch, reopen the last vault and (behind a setting) the last open tabs. The audit
  found recent-files exists but no session restore.
- **Tests:** restore reopens vault + tabs; gracefully handles a vault folder that moved/
  was deleted since last launch.

### WI-1.4 — Vault-scale file watching — M
- Extend `file_watcher.rs` to watch the vault root recursively (debounced), emitting
  tree-update events (file added/removed/renamed) distinct from the existing
  open-file `file:changed`. Update the tree without losing expansion state.
- **Tests:** add/remove/rename inside the vault updates the tree; rapid changes debounced;
  no duplicate reload of open files (reuse existing SAVE_SUPPRESS window).

## Phase 2 — Find anything (the daily driver)

### WI-2.1 — Global full-text search — M
- `search_vault` Tauri command: incremental full-text search across the vault
  (filename + content), returning ranked matches with line + snippet. Keep it simple
  first (streamed grep-style scan with an in-memory index), optimize later.
- `src/components/Sidebar/SearchPanel/` — query box, results grouped by file, click to
  open at match. Reuse the existing single-file search for in-document.
- **Tests:** Rust search (match ranking, case sensitivity, regex toggle, no results,
  binary/non-md skipped, large vault cap with a logged truncation per rule "no silent caps").

### WI-2.2 — Quick-open / `Cmd-P` fuzzy finder — S
- Command-palette-style modal: fuzzy-match filenames across the vault, Enter opens.
- Reuse the recent-files list as the empty-query default.
- **Tests:** fuzzy ranking, keyboard nav, Enter opens + adds tab, Escape closes.

## Phase 3 — Linked notes (the Obsidian identity)

### WI-3.1 — `[[wiki-link]]` support — M
- Stop escaping `[[` in `linkPlugin`; parse `[[Note]]` / `[[Note|alias]]` → resolved
  links. Autocomplete on `[[` (suggest vault files). Render as clickable in preview +
  WYSIWYG; click opens/creates the target.
- Index links during the vault walk (P4) for the backlink inverse index.
- **Tests:** parse `[[x]]`, `[[x|y]]`, unresolved link (create-on-click), link inside
  code fence is NOT a link, autocomplete suggestions.

### WI-3.2 — Backlinks panel — M
- Inverse index: for the active file, show "linked mentions" (files linking to it).
- `src/components/Sidebar/BacklinksPanel/` or a bottom dock.
- **Tests:** backlink index correctness, updates when a link is added/removed, handles
  rename (links to renamed file).

### WI-3.3 — Tags from frontmatter + inline — S
- Surface `tags:` frontmatter (P5) and inline `#tag`. A **Tags** sidebar panel lists
  tags with counts; click filters to tagged files.
- **Tests:** tag extraction (frontmatter list, inline, mixed), tag→file filter,
  `#tag` inside code/URL is not a tag.

### WI-3.4 — Graph view — L  **[optional / last]**
- Read-only force-directed graph over the link index. Nodes = notes, edges = links;
  click a node to open. Build only after the link index (WI-3.1/3.2) is solid.
- **Tests:** graph builds from the index (node/edge counts), click-to-open; render is
  visual-QA, not unit-tested.

## Acceptance Criteria

- [ ] User can open a folder as a vault; the file tree shows in the sidebar
- [ ] Single-file open still behaves exactly as today (no vault required)
- [ ] Sidebar hosts switchable panels: Files, Search, Outline (TOC preserved), Tags
- [ ] File tree supports new/rename/delete (with confirm) and reveal-in-Finder
- [ ] Last vault + (optionally) last tabs restore on launch; missing vault handled gracefully
- [ ] Vault-recursive file watching updates the tree without losing expansion state
- [ ] Global full-text search returns ranked, click-to-open results across the vault
- [ ] `Cmd-P` fuzzy file finder opens any vault file by name
- [ ] `[[wiki-links]]` parse, autocomplete, render clickable, and create-on-click
- [ ] Backlinks panel shows linked mentions for the active file
- [ ] Tags (frontmatter + inline) are listed and filterable
- [ ] (Optional) Graph view renders the link index and supports click-to-open
- [ ] All new IPC commands follow rule 50 (Result<T,String>, validated input) and log per rule 20

## Out-of-scope (this plan)

- Math/Mermaid/footnotes, PDF export, WYSIWYG find-replace, slash commands, custom
  themes — see the companion parity plan.
- Cloud sync, multi-device, publish/share.
- Plugin marketplace (explicit project constraint).
- Canvas/whiteboard, daily-notes templates (candidate later, not committed).

## Suggested sequencing

Phase 1 is the unlock — nothing else works without the vault + tree. Phase 2
(search + quick-open) delivers the most daily value per unit effort and should follow
immediately. Phase 3 is the differentiator but heaviest; **WI-3.4 graph view is
explicitly last and optional** — ship linked notes (3.1–3.3) before investing in
visualization. Phase 4 hardening (data-loss/encoding E2E) is shared with the companion
plan — land those tests there.

## Risks & open questions

- **Index scale:** thousands of files must index incrementally off-main-thread (P2).
  Validate with a large real vault before committing to the in-memory approach in WI-2.1.
- **Sidebar refactor blast radius:** `Sidebar/index.tsx` is currently TOC-only and
  untested (audit). The multi-panel refactor (WI-1.2) should add component tests as it
  goes, since it touches the most-used surface.
- **Wiki-link vs sanitization:** `[[` is currently escaped for a reason — re-enabling it
  must not reopen an injection vector. Parse to safe link nodes; keep DOMPurify on output.
