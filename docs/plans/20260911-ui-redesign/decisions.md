| E9 | WI-4.14 pushes outside text in with a **flushable owned debounce** (Q1). `@milkdown/plugin-listener` builds a new 200 ms debounce per transaction, closing over that transaction's doc (`lib/index.js:124-143`), so typing and then reloading inside 200 ms writes stale Markdown back over the reload. `MilkdownEditor` therefore owns its own doc-change observer, with a generation token scoped to (document id, editor instance) and invalidated on disposal. A push cancels the pending write-back, and the write-back is flushed synchronously before **every** dirty read: save, mode switch, tab switch, tab close, window close, draft autosave, export and the `BottomTabs.tsx:33` dirty check. Fresh-open sources (Reload, encoding reopen, draft recovery) use `replaceAll(md, true)`; MCP writes stay non-flush and are wrapped by `closeHistory`, whose trailing boundary is a separate transaction on the updated state. Pushes queue until the editor instance exists and defer while `view.composing`. An origin flag, not string equality, suppresses the editor's own echo. The `imagePastePlugin.ts:117` paste position and the `typoraKeymapPlugin.ts:238` link snapshot are invalidated on replace. | eng review 2026-09-12 (round 2, Codex consult) |
| E10 | Document ids become UUIDs, and a second open of the same file is caught by **canonical path**, not by id (Q2). A frontend-only check is not enough: `open_file_dialog` reads the file in Rust (`file.rs:1129`), so two concurrent opens both pass a pre-read lookup. A shared open coordinator coalesces in-flight opens by canonical path. `reload_file` (`file.rs:1408-1410`) builds a fresh `Document`, so reload and encoding reopen must carry the owner id forward or UUIDs will upsert a second entry. Dedupe is per window. Save As needs a destination-already-open policy, and draft matching by `original_path` must not merge two recovered buffers. | eng review 2026-09-12 (round 2, Codex consult) |

| E12 | `openDocumentFromPath` returns a **result union** instead of `null`-or-throw (Q4): `{status:"opened"}` \| `{status:"encoding"}` \| `{status:"failed", reason:"too_large"\|"other", name}`. Every union member is truthy, so the existing truthiness checks at `App.tsx:352` and `:857` must switch on `status` or they will log failures as successes. The action id is preserved so each start has exactly one terminal log, and detached (`void`) boundaries keep a terminal `catch` anyway. `useDocument.ts:49` holds a single `encodingIssue` slot, so a batch with two encoding failures loses the first; it becomes a queue. | eng review 2026-09-12 (round 2, Codex consult) |

| E14 | Insert-modal state is bound to **ownership tokens** rather than hoisted (Q6). | E17 | The `FileError` wire format is **unchanged** (S1). Changing the Rust representation buys nothing and breaks a shipped contract. Only `saveService.ts:39-40` interpolates a raw error into user-visible text — `"Save failed: [object Object]"`, because `err instanceof Error` is false for a plain object; `preferencesService.ts:78` and `useUpdater.ts:51-54` toast constants, so their damage is confined to log payloads. `useDocument.ts:35` is updated with it. | E18 | The file watcher **delivers the trailing event** instead of dropping it (S2). | E19 | All nine `listen()` call sites move to **one cancellation-safe subscription primitive** (S3) that takes a registration factory plus a committed handler ref updated in a layout effect, and subscribes on **event/window/enabled identity** rather than handler identity. Six sites assign `unlisten` after an `await` or a `.then()` with no cancellation flag (`App.tsx:374-396`, `:868-892`, `:1089-1103`, `useMenuEvents.ts:125-137`, `useMcpEvents.ts:313-351`, `useTheme.ts:22-42`); `useFileWatcher.ts:28-61` shows the correct `cancelled`-flag shape. Tauri's `listen()` registers a new callback per call (`@tauri-apps/api/event.js:74`), so a duplicate registration duplicates menu actions and document creation — behaviorally harmful, not cosmetic. Correction to an earlier claim: `useTheme`'s `.then()` does not make cleanup run synchronously; React runs cleanup at unmount or re-run, and the leak needs cleanup to precede the completion of registration. | eng review 2026-09-12 (round 2, Codex consult) |
| E20 | Command logging goes through a **`loggedOperation` wrapper** (S4) that logs Start *before* validation and exactly one terminal outcome derived from the `Result`. `commands/preferences.rs:35,48` is the model.
