## 主要缺口与完成条件

1. **MUST — 3.5 尚未形成用户可见效果。** `src/stores/tocStore.ts:79` 每次生成新 key，并清空 `activeEntryId`、`collapsedIds`。`coordinateHeadingKeys` 没有生产调用方。完成条件应包含算法接线、按文档隔离、删除后清理，以及正文普通编辑前后折叠/活动态保留的行为测试。
2. **MUST — 3.6 的重复标题问题仍在。** `useTOC` 的导航与 observer 注册都退回文字首个命中；只修其中一个不算完成。应验证两个同名标题分别导航、分别高亮，并覆盖切换编辑模式与文档后的清理。
3. **MUST — 已触及的 hook 仍违反 store 订阅规则。** `src/hooks/useTOC.ts:52` 继续整店订阅并解构 `useTOCStore()`。接线收尾时应按项目契约使用选择器、在外部回调里读取新鲜状态，补相应生命周期测试。
4. **性能风险 — 主线程全量解析，加上重复前缀计行。** `useTOC` 在 300 ms 去抖后同步解析全文；`tocService.ts:211` 对每个标题重新统计文件前缀换行。标题数 H、行数 L 增长时，计行部分有 O(H×L) 风险。这是源码复杂度判断，不是本次计时；不能把历史所有耗时都归给 Lezer。3.8 应区分树构建、标题提取、位置计算成本，并补缩放律测试或改成一次行索引/单调扫描。
5. **MUST — 排期状态不一致。** 总览第 26 行说 3.3–3.8 未开工，明细第 144–145 行却正确写 3.3/3.4 已交付；3.7 的“store 测试为零”也不再符合当前工作区。应分别写清 HEAD 已交付、工作区进行中与验收尚欠，避免下一轮重复开发或误放行。
6. **尚未闭合的原有门禁。** CI 没有 PR 触发；ESLint 是 P 中后续规则的硬前置。D6 与性能出口的承载工作项需明确。CSP 缺少 connect-src、logger 读设置失败回默认值、表格写入先返回 202 的情况仍能在代码中定位；本次没有把这些旧缺陷伪装成新发现，也没有复测其所有用户影响。
