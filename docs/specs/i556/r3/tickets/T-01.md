## What to build

The landing guard becomes the single landing command for both delegator routes. It takes a SHA, and optionally an item
id and `--target release/<x.y>` (the default target is `master`). Before landing it checks two things:
- a landing verifier record says PASS at that exact SHA;
- the item's PR has that SHA as its head and the target branch as its base, with a green `ci-gate`.

Then it fast-forwards the target branch and pushes it. Every refusal names each failed check:
- a missing record, a record for another SHA, ISSUES or BLOCKED, or two records for one SHA with different verdicts;
- a red or absent `ci-gate`, a PR head that is not the SHA, or a PR base that is not the target;
- GitHub unreachable, or a record that cannot be read or parsed.

Supporting pieces:
- **Records.** They are read from a fixed root under the password-database home's `.mdpro-redesign`. Outside test mode,
  the command refuses when `HOME` differs from that home. Another root is honoured only in the existing test mode, and
  only under the temporary directory.
- **Verification-record template.** A new template serves both producers: the verifier agent definition, which now
  writes its own record file on Claude, and the Codex delegator's procedure. It fixes:
  - the record's file name;
  - the VERDICT grammar, with no qualifier inside the verdict token;
  - the DEVICE grammar, including `<AC>=waived:<id>`;
  - the optional `CARRIED <id>[, …]` line.

  Until T-04 lands, a record with a `CARRIED` line or a `waived:` AC is refused, so the gate fails closed.
- **Path module.** One module classifies every tracked path as one of:
  - a Policy file, gate-sensitive or not;
  - a Knowledge document;
  - code.

  It uses the spec's lists. The existing docs-only mode reads it, though its behaviour does not change until T-05.
- **Replay mode.** It is read-only: it takes an explicit historical parent, accepts a merged PR, writes nothing, and
  reports every check.
- **`--item` is optional.** Without it, the verifier lookup is by SHA.

The parsers, the path module and the guard are separate modules under `scripts/codex-rules/`, within rule 50's limit.

## Acceptance criteria

- [ ] Given a PASS verifier record for the SHA, and a green `ci-gate` on a PR whose head is the SHA, the command lands
      it, and `origin/master` moves to the SHA.
- [ ] With `--target release/<x.y>` and a PR based on that branch, the release branch moves and `master` does not. A PR
      based on another branch is refused, naming the CI check.
- [ ] Each of these is refused, naming the verifier check, and `master` does not move:
      - a missing verifier record;
      - a record for another SHA;
      - ISSUES or BLOCKED;
      - a qualifier inside the verdict token;
      - two conflicting records;
      - an unparseable VERDICT line.
- [ ] A red `ci-gate`, an absent `ci-gate`, or a PR head that is not the SHA is refused, naming the CI check.
- [ ] GitHub unreachable (the fake `gh` fails) is refused, naming the check that could not run.
- [ ] A records-root override outside test mode is ignored. A `HOME` that differs from the password-database home is
      refused.
- [ ] A verifier record with a `CARRIED` line or a `waived:` AC is refused, naming the verifier check. T-04 lifts this.
- [ ] Replay mode on a fixture merged PR with an explicit parent reports each check and writes nothing: refs, index and
      files are unchanged.
- [ ] The path module classifies every `git ls-files` path exactly once (fixture test). Its Policy, gate-sensitive and
      Knowledge lists equal the spec's. Every tracked file under a Policy prefix that has mode `100755`, or is a
      `*.mjs`, `*.py`, `*.sh` or `*.json` file, is gate-sensitive.
- [ ] The verification-record template and the verifier agent definition's output section both parse under the pinned
      grammar (fixture test). The agent definition says it writes the record file itself.
- [ ] Without `--item`, the existing Codex `land-guard.mjs <sha>` call still works, and the verifier lookup is by SHA.
- [ ] Proved at the landing-command process seam (temporary repo, bare origin, fake `gh`, fixture records root).
