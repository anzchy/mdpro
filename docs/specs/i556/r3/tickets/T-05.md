## What to build

Policy files leave the delegator's docs-only path:
- docs-only mode lands Knowledge documents only, as T-01's path module classifies them;
- it refuses any commit touching a Policy file, and points to the PR route;
- the audit dimensions file keeps its ADR-0146 High-tier PR rule.

The PR route relies on these policy tests:
- **Change classification** treats every Policy file as code. `AGENTS.md` and `CLAUDE.md` leave the prose list, and
  `docs/agents/**` joins them as code.
- **A new path check** refuses any Policy file that names a path starting with a denylisted, known-wrong prefix. The
  first entry is `/Users/jackcheng/`. It behaves the same on macOS and on Ubuntu CI.
- **Both run in the rules check.**

## Acceptance criteria

- [ ] Docs-only on Knowledge documents only lands. This includes `design/DESIGN.md`, `GLOSSARY.md` and `progress.md`.
- [ ] Docs-only that touches any of these is refused, naming the PR route:
      - `CLAUDE.md` or `AGENTS.md`;
      - a file under `.claude/`, `.agents/`, `.codex/` or `scripts/codex-rules/`;
      - a file under `docs/agents/`.

      For a gate-sensitive path, the refusal also says the PR must be `audited`.
- [ ] Change classification marks each Policy glob as code (change-scope tests, one case per glob).
- [ ] The path check refuses a fixture Policy file naming `/Users/jackcheng/…`. It passes one naming `/Users/jack/…`,
      `~/.mdpro-redesign/…` and a `<sha7>` placeholder.
- [ ] The rules check runs both, and passes on the current tree once #556 item 1 has landed.
