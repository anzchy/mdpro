## What to build

The landing guard becomes the single landing command for both delegator routes. Given a SHA, and optionally an item id,
it first checks:
- that a landing verifier record says PASS at that exact SHA;
- that the item's PR head is that SHA, with a green `ci-gate`.

Then it fast-forwards `master` and pushes. Every refusal names each failed check:
- a missing record, a record for another SHA, ISSUES or BLOCKED, or two records for one SHA with different verdicts;
- a red or absent `ci-gate`, or a PR head that is not the SHA;
- GitHub unreachable, or a record that cannot be read or parsed.

Supporting pieces:
- **Records.** They are read from a fixed root under `$HOME/.mdpro-redesign`. Another root is honoured only in the
  existing test mode, and only under the temporary directory.
- **Verification-record template.** A new template serves both producers, the verifier agent definition and the Codex
  delegator's procedure. It fixes the record's file name and its VERDICT and DEVICE grammar, with no qualifier inside
  the verdict token. On the Claude route the delegator saves the verifier's output verbatim.
- **Path module.** One module classifies every tracked path as a Policy file, a Knowledge document or code, using the
  path lists in the spec. The existing docs-only mode reads it, though its behaviour does not change until T-05.
- **Replay mode.** Read-only: it takes an explicit historical parent, accepts a merged PR, writes nothing, and reports
  every check.

The parsers, the path module and the guard are separate modules under rule 50's limit.

## Acceptance criteria

- [ ] Given a PASS verifier record for the SHA, and a green `ci-gate` on a PR whose head is the SHA, the command lands
      it and `origin/master` moves to the SHA.
- [ ] A missing verifier record, a record for another SHA, ISSUES, BLOCKED, a qualifier inside the verdict token, two
      conflicting records, or an unparseable VERDICT line is refused, naming the verifier check. `master` does not move.
- [ ] A red `ci-gate`, an absent `ci-gate`, or a PR head that is not the SHA is refused, naming the CI check.
- [ ] GitHub unreachable (the fake `gh` fails) is refused, naming the check that could not run.
- [ ] A records-root override outside test mode is ignored.
- [ ] Replay mode on a fixture merged PR with an explicit parent reports each check, and writes nothing: refs, index and
      files are unchanged.
- [ ] Every `git ls-files` path is classified exactly once by the path module (fixture test). The Policy and Knowledge
      lists equal the spec's.
- [ ] The verification-record template and the verifier agent definition's output section both parse under the pinned
      grammar (fixture test).
- [ ] Without `--item`, the existing Codex `land-guard.mjs <sha>` call still works, and the verifier lookup is by SHA.
- [ ] Proved at the landing-command process seam (temporary repo, bare origin, fake `gh`, fixture records root).
