## What to build

The landing command also requires the auditors' clearance for the exact SHA. For each auditor it reads that auditor's
highest-round report for the item, using the spec's discovery pattern with request, challenge and plan files excluded.
The report must:
- name a range that ends at the SHA, or at an audited head from which the SHA is an accepted rebase;
- carry a `COUNT … · BLOCKING` line whose blocking counts are zero Critical and zero High.

An accepted rebase is proved by `git range-diff`: every commit pair `=`, none added or dropped, and the new base on
fetched `origin/master`. Both live VERDICT spellings are accepted: gpt's, and opus's fenced form with `fix diff` or
`base`. A `SECURITY COUNT` line is never taken for the BLOCKING line.

A PR whose body says `Policy route: routine`, when every changed path is a Policy file or a Knowledge document, needs
both auditors' Low-tier mini reports and `ci-gate`, and no verifier record: the command skips T-01's verifier check for
it. `Policy route: audited`, or no marker, needs both auditors at the tier the request names and the verifier.

## Acceptance criteria

- [ ] With T-01's evidence present, and both auditors' latest reports clear for the SHA, the landing proceeds.
- [ ] Either auditor's latest report counting a blocking Critical or High is refused, naming that auditor.
- [ ] A latest report whose range ends at an older head is refused, even if an earlier round named the SHA.
- [ ] A missing report for either auditor, or an unparseable count line, is refused.
- [ ] A rebase whose range-diff is all `=`, on a new base in `origin/master`, is accepted. One that shows a `!`, an added
      commit or a dropped commit is refused, even when `src`, `tests` and `src-tauri` are tree-identical.
- [ ] A gpt report with `SECURITY COUNT` after `COUNT`, and an opus report in its fenced spelling, are both read
      correctly (fixtures copied from the live shapes).
- [ ] A routine Policy PR with clear Low reports from both auditors and a green `ci-gate` lands with no verifier record.
      Missing either auditor's report is refused, naming that auditor. The same PR touching a code path is refused,
      naming the Policy route, and then needs the verifier again.
- [ ] Proved at the landing-command process seam.
