## What to build

The landing command also requires device evidence bound to what lands. It reads the verifier record's DEVICE line,
which is either `none` or a comma-separated list. Each entry is one device AC, written either as
`<AC>=<report basename>@<releaseId sha40>` or as `<AC>=waived:<exception id>`.

Each cited report must exist under the device folder and carry the line `IDENTITY releaseId <version>[-dev]@<sha40>`,
with the same SHA. The `-dev` suffix is absent for a release-type verify build. That SHA must have ADR-0144
decision 5's identity with the landing SHA:
- no change between them inside the identity tree, which is the whole tree minus `docs/` other than `docs/test/cards/`,
  minus `tests/` other than `tests/manual-fixtures/`, and minus `.claude/`, `.agents/`, `.codex/` and `CHANGELOG.md`;
- each cited card's blob unchanged.

A `waived:` entry parses. Until T-04 lands, it is refused.

The device-brief template is amended so that every report carries the IDENTITY line. Two things stay with the verifier
and are recorded as limits: the AC-text hash, and whether the report says PASS.

## Acceptance criteria

- [ ] A DEVICE line of `none` adds no requirement.
- [ ] Cited reports that exist, and whose IDENTITY SHA has the same identity as the landing SHA, let the landing
      proceed. A docs-only change between the two counts as the same identity.
- [ ] A cited report is refused, naming the device check, when it is missing, has no IDENTITY line, or has an IDENTITY
      SHA that differs from the DEVICE line.
- [ ] A change inside the identity tree, or to a cited card, between the release SHA and the landing SHA is refused.
- [ ] An IDENTITY line in the release-build form (no `-dev`) parses and is checked the same way.
- [ ] A `<AC>=waived:<id>` entry parses, and is refused, naming the device check, until T-04's exception reader accepts
      it.
- [ ] An unparseable DEVICE line is refused.
- [ ] The verification-record template's DEVICE line and the device-brief template's IDENTITY line, in both build forms,
      match the pinned grammar (fixture test).
- [ ] Proved at the landing-command process seam.
