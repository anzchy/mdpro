## What to build

The switch-over: landing becomes enforced on both routes.

**The Claude route.** The main checkout gets the delegator overlay, through the existing installer's delegator role.
The herdr-delegator pane is relaunched with `MDPRO_ROLE=delegator`.

**The role guard.** In the main worktree, an unset `MDPRO_ROLE` counts as `delegator`. Outside it, an unset role is
unchanged.

The delegator branch refuses:
- a raw `git merge` on `master` or a `release/*` branch;
- any push to `master` or `release/*`, in every spelling: `HEAD:<branch>`, `+<branch>`, `refs/heads/<branch>`, a bare
  `git push` or `git push origin` on that branch, `--all` and `--mirror`. It reuses the existing refspec helper;
- `gh pr merge` in any form, and `gh api` with a `pulls/<n>/merge` path.

It allows ordinary git, `git commit` on `master`, and the landing command, including `--create-release`, whose own
git calls are unaffected.

**Codex.** The installer's delegator overlay body gains a forbidden `git merge` rule. The shared rules already forbid
`git push` and `gh pr merge`. The Codex overlay is reinstalled and the pane restarted.

**Docs.** These name the landing command as the only landing and docs-push path, on both routes, per ADR-0159:
- rules 70 and 71. Rule 70's sentence "No role set means no checks, so the delegator and the user's own sessions run
  unchanged" becomes "No role set means no checks, except in the main checkout, where an unset role counts as
  `delegator`";
- the delegator Skill and its guide, which show `--item` and `--target release/<x.y>`;
- the delegator templates: `landing-docs-checklist.md`, `audit-request-template.md` and `confirm-request-template.md`;
- the codex-rules README;
- `AGENTS.md` § Delegator routing;
- `CLAUDE.md` § Release Workflow and § Plan Status.

`--item` stays optional.

**ADR-0159** moves from Proposed to Accepted on the user's word.

**Replays.** Before enforcement starts, replay mode is run on the real records:

  - verifier: there is no record for `5a5b0110`;
  - auditor:opus: its last report, `ADR0149-entry-r2.md`, is at `d5ea3b49`;
  - device: the check cannot run without a verifier record.
- **#549:** refused. Its verifier record is for `860db824`, not `5b55447f`. Both auditors end at `66cc944c`, and
