## What to build

On Windows, Toggle Sidebar's default binding becomes **Ctrl+Shift+1**, and **Ctrl+Shift+L** stays as a secondary binding, so
both chords toggle the sidebar. The Windows View menu shows Ctrl+Shift+1 and takes it from the command table. Settings →
Keyboard Shortcuts lists it as the default, with Ctrl+Shift+L as the secondary, and "Reset to default" restores it. A fresh
Windows install starts with it, and a Windows config on defaults version 1 that still holds the v1 default migrates to it.
A chord the user chose is kept. macOS (⌘⇧L) and Linux (Ctrl+Shift+L, no secondary) do not change, and the defaults version
stays 2.

The command table remains the single source (rule 41). The row builder gains a per-platform value for this one row. The
keydown hook gets a Windows-only secondary that logs the chord pressed. The Rust host defaults, the migration and the
applied-shortcuts resolution take the platform as a value, so that the Windows case is tested on macOS and Linux. Editor
keymaps keep their precedence: on AZERTY, Ctrl+Shift+& in the editor stays Heading 1. The keyboard shortcuts guide, the
menu plan's v2 defaults table, the M1b device chord input, the semantic-find plan's key note, the feature ledger and
`CHANGELOG.md` change in the same PR.

## Acceptance criteria

- [ ] AC-1 (unit, command table): the v2 bindings for Toggle Sidebar resolve as follows.
  - Windows: primary Ctrl+Shift+1, secondary Ctrl+Shift+L.
  - macOS: ⌘⇧L, with no secondary.
  - Linux: Ctrl+Shift+L, with no secondary.
  - v1 is unchanged on every platform, and the binding-conflict laws hold: Ctrl+Shift+1 is no other Windows action's
    default or secondary.
  - The narrowed invariants hold:
    - the rows whose Linux and Windows values differ are exactly `view.sidebar`, and only in its v2 primary and v2
      secondaries;
    - the v2 secondaries are F6, F3 and Shift+F3 on every platform, plus Ctrl+Shift+L on Windows `view.sidebar` only;
    - the changed-field counts are 15 (macOS), 21 (Windows) and 20 (Linux), and Windows' set is Linux's plus
      `viewToggleSidebar`.
  - The generated menu layout is fresh.
- [ ] AC-2 (unit, keydown dispatch), with the hook on the Windows platform at defaults version 2:
  - Ctrl+Shift+1 (`!` with code `Digit1`) and Ctrl+Shift+L each trigger `view.toggle_sidebar` exactly once and log
    `ui.shortcut.trigger` naming the chord that matched (`Cmd+Shift+1`, `Cmd+Shift+L`).
  - Neither chord fires any other action.
  - With the primary rebound, cleared, or set to Ctrl+Shift+L, Ctrl+Shift+L still triggers exactly once.
  - On Linux, Ctrl+Shift+L triggers and Ctrl+Shift+1 does nothing. On Windows at defaults version 1, the secondary is
    inactive. macOS is unchanged.
- [ ] AC-3 (unit, composed editors, Windows):
  - In WYSIWYG and in Source, with focus in the editor and with focus outside it, Ctrl+Shift+1 toggles the sidebar once,
    leaves the document unchanged and runs no editor command.
  - An AZERTY keydown (`1` with Shift, code `Digit1`) runs Heading 1 once and does not toggle in either editor. With focus
    outside the editors, it toggles once.
- [ ] AC-4 (unit, Settings):
  - "Reset to default" yields Ctrl+Shift+1 for Windows v2, and Ctrl+Shift+L for Linux v2, macOS v2 and Windows v1.
  - On Windows, the Toggle Sidebar row shows default Ctrl+Shift+1 and secondary Ctrl+Shift+L.
  - Assigning either chord to another action is flagged as a conflict with Toggle Sidebar.
  - The launch conflict notice names Ctrl+Shift+1 for a yielded Toggle Sidebar on Windows.
- [ ] AC-5 (Rust unit; every case passes the platform as a value and runs on the macOS and Linux test hosts):
  - The host defaults give Ctrl+Shift+1 for Windows and Ctrl+Shift+L for macOS and Linux. Every field matches the
    generated layout's v2 default on all three platforms.
  - The Windows migration plan:
    - moves a v1 config holding Ctrl+Shift+L to Ctrl+Shift+1;
    - keeps a custom value;
    - keeps a v2-stamped Ctrl+Shift+L.

    The Linux plan keeps Ctrl+Shift+L for the same v1 config. Every changed v1 default becomes its v2 default, on each
    platform.
  - Applied shortcuts for Windows bind Ctrl+Shift+1 and keep Ctrl+Shift+L owned by Toggle Sidebar.
  - The native View menu's Toggle Sidebar accelerator is exactly `CmdOrCtrl+Shift+1` on Windows and `CmdOrCtrl+Shift+L`
    on Linux. The off-Mac menu tree baselines for the two differ only in that line. No literal sidebar accelerator is left
    in the native menu code.
- [ ] AC-6 (docs): these all match the table:
  - the guide's Toggle Sidebar row, split by platform;
  - the menu plan's v2 defaults table, citing ADR-0158;
  - the M1b device chord input: two new Windows rows, and the header no longer says the Windows column covers Linux. Its
    row-count test expects 76;
  - the semantic-find plan's key question, with a note that Microsoft Pinyin and Sogou bind Ctrl+Shift+F;
  - the feature-ledger shortcut row and sidebar toggle row;
  - a `CHANGELOG.md` Unreleased line.

  `pnpm ledger:check` passes.
