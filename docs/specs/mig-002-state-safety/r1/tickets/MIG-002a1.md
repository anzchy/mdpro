## What to build

**MIG-002a1: the App journey harness, proved by two save clauses.** This is the tracer bullet: the first App journey that goes from a keystroke in the real `<App />` to bytes in the write log, plus the refusal path that proves a failed flush writes nothing.

- **The journey harness** renders the real `<App />` with real Milkdown and real stores over MIG-001a's fake Tauri boundary. It adds to that boundary:
  - the webview quit event bus, with `quit_guard_reply` capture;
  - window close requests;
  - `menu:action` delivery;
  - dialog fakes (ask, message, save, open) answered by script;
  - the IPC commands the App calls at startup and in journeys (launch paths, draft list, logging, the open dialog, MCP sync, watch commands);
  - a `file:changed` emitter with the origin window label;
  - an MCP event emitter;
  - updater and process stubs.

  An IPC call it doesn't model throws. MIG-001's existing boundary behaviour is unchanged.
- **Harness helpers:** typing and IME composition, fake time with `advance(ms)` (real timers only with a stated reason), StrictMode as an option, `readTokens(id)`, the real-serializer break and heal (D92's shape, promoted), and teardown checks (no pending timers, live listeners or registered flushers after a journey).
- **The known-limitation registry** and its check test, which rejects `ref: pending` and malformed records.
- **Clauses** (spec #733 § Contract clauses):
  - a-C2: Cmd+S before the edit-sync delay elapses writes the latest typed text.
  - a-C4: a failed flush writes nothing, does not mark the document clean, and is never reported as success.
- **Row a's serializer-throws journey**, which pins today's outcome as input for MIG-005/013.

StrictMode clauses: a-C2. Reused suites to cite: `d92-failed-flush-blocks-switch`, `d92-failed-flush-callers`, `d214-edit-sync-baseline`, `flush-call-sites`. Likely MIG-005 host sites at 7bb42efb: none direct, since save reaches the editor through the flush registry; confirm by grep.

## Acceptance criteria

- [ ] Harness self-tests pass:
  - a save records exact bytes;
  - an unedited open records no write;
  - a scripted dialog answer reaches the app;
  - a quit reply is captured;
  - an unmodelled IPC call throws;
  - a journey that leaves a timer, a listener or a flusher behind fails;
  - the real serializer break yields `failed`, and the heal restores it;
  - `readTokens` reports a known delta;
  - Milkdown mounts under fake timers.

  If Milkdown can't mount under fake timers, the fallback goes to the user through the delegator before any further journey is written.
- [ ] The corpus suite (MIG-001) stays green, with its boundary behaviour unchanged.
- [ ] The handoff reports the harness's mount cost per journey, so the delegator can check the §17 budget.
- [ ] No card: row a's card is a2's.
