## What to build

Go-live. From this landing, every implementor brief on either runtime follows `jack-tdd-workflow`, and Codex no longer uses tdd-guardian.

**Routing.**
- The brief template and `prompt.sh`'s brief text name the skill for both runtimes.
- Before sending a brief, `prompt.sh` checks the target runtime's installed Matt Pocock skills plugin with the T-01 version function. It refuses to send (fail closed) when that plugin is missing, older than 1.3.1 or malformed, and says why.
- The brief template keeps the per-item skill-version pin, and its receipt-id form becomes the skill's `<ID>-S<n>` / `<ID>-ACC`.

**The attack prompt moves.** The attack prompt moves from the delegator skill's templates into `jack-tdd-workflow`, and every reference is updated: `prompt.sh`, rule 71 § Briefs, rule 12, the brief template, and the routing test's expected text.

**The attacker, on both runtimes.**
- The attacker is a fresh subagent given the skill's attack prompt, never a fork or a resumed agent. On Claude it is an Opus subagent at default effort; on Codex it is a fresh Codex agent at its default model and effort, started as a new `codex exec` process with no resumed session and given only the attack prompt, the brief and the matrix.
- Rule 71's Models row for `mdpro-spec-adversary`, ADR-0138 decision 5's stop-rule sentence and ADR-0139 decision 3's routine routing no longer route anything.
- The two `.codex/agents/mdpro-spec-adversary*.toml` agents are removed.

**The rules.**
- Rule 71 § Briefs and rule 12's implementation section keep the law (the matrix is attacked before any RED, who rules on gaps, the handoff table) and point at the skill for the method. Their separate Claude and Codex variants become one.
- Rule 71 step 4's "all REDs first" is replaced by cycles for every implementor item, gated or not.
- A new seam or changed behaviour still stops for the delegator (rule 12).
- Rule 70's "the tdd-guardian lanes are the author's job" and rule 10's `slow` lane name become plain lane names: the lanes stay, the plugin is not named.
- AGENTS.md's feature table points Codex at the skill.
- Rule 10 keeps its receipt commands.

**What stays.** These keep naming tdd-guardian, and the contract test carries them as an explicit allowlist:
- receipt storage under `.claude/tdd-guardian/` and its config;
- dated guides and historical handoffs;
- the 2026-10-20 history paragraph in rule 71;
- the archived Codex TDD port.

The user's own step, outside the repo: disabling the tdd-guardian plugin in the shared Codex install.
