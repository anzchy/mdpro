## What to build

The `jack-tdd-workflow` project skill exists, can be read by both runtimes, and is guarded by a test. Nothing outside the skill changes yet: no brief, rule, AGENTS.md or `prompt.sh` text routes to it, and the attack prompt still lives at its current path (T-02 moves it).

An implementor who opened the skill would find the whole method, from test matrix to handoff table:
- the matrix case classes;
- the fresh-subagent matrix attack: once per grant, at most one re-attack, a counter-proof for every rejected gap;
- the optional acceptance check first, recorded under its own id `<ID>-ACC`;
- cycles: one case → RED receipt `<ID>-S<n>` → minimal change → `verify` → small refactor with tests green;
- one case per cycle: one intended assertion and one `--test` file per record, with no batched unit REDs;
- the matrix amendment rules: a new case inside an existing seam and AC is "added in cycle n" with no re-attack, while a new seam or a changed behaviour stops for the delegator;
- the recorded-line correction route;
- raw-green naming;
- `/code-review` before the handoff, and `/diagnosing-bugs` for D items;
- the self-acceptance table.

Receipt commands stay in rule 10, and the receipt CLI stays where it is. The skill carries a thin wrapper that calls the receipt CLI in four modes (frontend and Rust, record and verify) running the commands the spec's Receipts table gives (three of them stated in rule 10), so an implementor needs nothing outside the skill to record or verify a receipt.

For the open PR #577, r5 is amended in place on the same branch: the wrapper arrives as new cycles with new `T567-` RED receipts after the last recorded one, the earlier receipts stay as recorded, and nothing already recorded is voided. The skill cites its primary sources and Matt Pocock's `tdd`, `code-review` and `diagnosing-bugs`.

The matrix template is an attachment of the skill. A version check decides whether an installed Matt Pocock skills plugin meets the 1.3.1 minimum. It has two parts: a pure function, tested on fixture caches, and a live check that runs it on the real Claude and Codex cache roots, and also reads, without writing, that each runtime has the plugin enabled (Claude's `enabledPlugins`, Codex's plugin entry in its config), in one macOS-only case declared in `tests/ci-inventory.json`.

GLOSSARY's "TDD" section and ADR-0161 (then Proposed, Accepted 2026-10-31) were committed with the planning snapshot. This ticket keeps them and does not edit them.
