## What to build

A `master-push.yml` workflow, separate from `ci.yml`, on push to `master` (DCT-r2-D11).

- **Setup.** No concurrency group. Permissions `contents: read`, `pull-requests: read` and `actions: read`. `fetch-depth: 0`.
- **Range.** It checks every commit since the `after` SHA of the latest earlier run that concluded `success`. A red, failed or cancelled run does not move the start. With no earlier green run, it starts at the earliest run's `before`.
- **Detector.** A commit that touches a `policy` or `code` path passes only when it is an ancestor of, or equal to, the head H of an associated PR whose `ci-gate` concluded `success` on H, and H is an ancestor of, or equal to, this push's `after`. A commit with a green D12 retro run on that exact SHA also passes. Any API, git or range failure fails the run.
- **Reader re-run.** The workflow also re-runs the readers of every prose Gate input in the range, and `journeys:check --base <range start>`.

**Red-master hold.** The landing command, in both modes, refuses while the `master-push.yml` run for `origin/master`'s HEAD is red, unless the landing is `--repair <run-id>` naming that run (which still passes every other gate). It also refuses while that run is in progress or missing, or when the lookup fails. The hold applies once `master-push.yml` exists in `origin/master`'s tree. Rule 70 § Commits item 2 gains this landing condition in the same commit as the entry.

When the detector fires, the delegator follows the exact-SHA retro route (D12): push `retro/<sha7>` at the slipped SHA, dispatch `ci.yml` on it with `base=<first parent>` (full lane), and record a gate-exception row, landed with `--repair`. That route goes into the delegator skill.

The "master push checks" entry rides this PR, and `ci.yml`'s header gains a pointer to the new workflow. `ci.yml` keeps no push-to-`master` and no `schedule` trigger.

Spec: DCT-r2-D11, D12, D20; stories 7–9.

## Acceptance criteria

- [ ] AC-1 (unit, seam 3, fixture commit graphs and stubbed API): the detector:
  - passes a PR-less prose commit;
  - passes a policy or code commit at, or below, a PR head with a green `ci-gate` that is itself at or below `after`;
  - fails a raw push of a strict prefix of a green PR head;
  - passes a commit with a green retro run on its exact SHA;
  - fails one with no PR;
  - fails one whose PR head's `ci-gate` was red;
  - fails on an API error;
  - fails on an unresolvable range.
- [ ] AC-2 (unit, seam 3): the range starts at the last green run's `after` SHA. Three pushes whose middle run was cancelled are all checked; after a red run (reader failure, detector failure, or a lookup failure that checked nothing), the next push re-checks that red run's commits and Gate inputs. With no green run, it starts at the earliest run's `before`.
- [ ] AC-3 (unit, seam 3): `master-push.yml` has the three permissions, `fetch-depth: 0` and no `concurrency`. `ci.yml` has no push-to-`master` or `schedule` trigger.
- [ ] AC-4 (unit, seam 3): the reader re-run selects the readers of the prose Gate inputs in the range, and nothing for a range without one.
- [ ] AC-5: the delegator skill names the retro route: the branch, the dispatch command with its base, the gate-exception row's fields, the user asked only on red, and no revert.
- [ ] AC-6 (unit, seam 3, stubbed API): the landing command, in both modes, refuses when HEAD's `master-push` run is red, in progress, missing, or the lookup fails, naming the reason. It lands a `--repair <run-id>` naming that red run when every other gate passes, and refuses a `--repair` naming any other run. It applies no hold when `master-push.yml` is absent from `origin/master`'s tree.
- [ ] AC-7: the entry, rule 70 § Commits item 2's new landing condition and the delegator skill's hold-and-repair steps land in one commit. The entry is indexed. Both auditors plan-reviewed it.
