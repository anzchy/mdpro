## Parent

#594 (spec r3). Ticket **T-07** (issue #601, revised; it absorbs r1's T-08, issue #602). High tier, gate-sensitive.

## What to build

**macOS (DCT-r2-D18).** On a `code` PR with `rust=true`, a separate `rust-test-macos` job runs. It has a 45-minute timeout, is always in `ci-gate`'s `needs`, and is required through T-02's rule. `frontend` stays Ubuntu-only on PRs, and tags keep their matrix. Both new jobs also run on dispatch; a green dispatch run on the T-07 branch head (`gh workflow run ci.yml --ref <branch>`) proves the macOS cold-cache time before the job becomes required.

**Windows (D19).** A `rust-windows` job runs on `rust=true` PRs. It creates the `mdpro_mcp-x86_64-pc-windows-msvc.exe` sidecar stub, then runs `cargo test` and `pnpm build`. It stays outside `ci-gate`. When the head is red, `rust-windows-base` runs the same steps on the PR's base SHA in the same run. Counting starts at its first green run after T-07 lands; a Windows red does not hold T-07's handoff.

**The delegator skill** gains the series rules:
- the unit is the latest completed attempt on a distinct head SHA;
- green advances the count, red resets it, and cancelled or skipped runs do neither;
- each counted run is a row in `docs/audit/audit-log.md` § Windows CI series;
- a red head with a green base goes into the audit request as a Medium, and the audit request waits for `rust-windows-base` to conclude;
- ten in a row allow a promotion entry.

**Records.** The "Rust on macOS and Windows" entry lands with rule 70 `#pull-request-ci`'s platform text, and ADR-0095 decision 7 gains its line for "macOS runs on `v*` tags".

Spec: DCT-r2-D18–D20; stories 30–35.

## Acceptance criteria

- [ ] AC-1 (unit, seam 3, behavioural): the gate script requires `rust-test-macos` success when `scope=code` and `rust=true`. It accepts `skipped` only when `scope` succeeded and `scope≠code` or `rust=false`, and fails on a missing `rust` output.
- [ ] AC-2 (unit, seam 3): `rust-test-macos` is a separate job in `needs`, with `timeout-minutes: 45`. `frontend` has no macOS leg on PRs. The tag matrix is unchanged.
- [ ] AC-3 (unit, seam 3): `rust-windows` creates the Windows stub before `cargo test`, runs on `rust=true`, and is not in `needs`. `rust-windows-base` runs only when `rust-windows` failed, and checks out the PR's base SHA. No installer step runs on PRs.
- [ ] AC-4 (CI): the handoff links a green dispatch run of `rust-test-macos` on the T-07 branch head, and the Windows jobs' result on the same run (green or red).
- [ ] AC-5: the delegator skill names the series rules, and the audit log gains the empty § Windows CI series table.
- [ ] AC-6: the entry, the rule 70 text and ADR-0095's dated line land in one commit. The entry is indexed and was plan-reviewed by both auditors.
