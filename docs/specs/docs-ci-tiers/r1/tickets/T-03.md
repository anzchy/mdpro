## Parent

#594. Ticket **T-03**. High tier, gate-sensitive.

## What to build

The direct path is enforced on both routes. On the Claude route, `role-guard.sh` gains a delegator branch that refuses a raw `git push` to `master` outside the landing command (the Codex route already has `land-guard`). After every push to `master`, a new check finds any pushed commit that has no associated PR and touches a `policy` or `code` path, and fails.

When it fires, the delegator records a gate-exception row, opens a PR from `master` that runs `doc-policy` or the full lane on that commit, and asks the user only if that is red. There is no revert. This procedure is written into the delegator skill.

Spec: DCT-r1-D5 (guard), D8; stories 4–6.

## Acceptance criteria

- [ ] AC-1 (unit, seam 3): with the delegator role set, the guard refuses a raw `git push` to `master` (including `git -C` and `origin HEAD:master` spellings) and allows the landing command's own push.
- [ ] AC-2 (unit, seam 3): the guard's other roles are unchanged.
- [ ] AC-3 (unit, seam 1): the post-hoc check classifies each pushed commit's paths with the T-01 classifier and fails on a PR-less commit touching `policy` or `code`; it passes on a PR-less `prose` commit and on a commit with an associated PR.
- [ ] AC-4 (unit, seam 3): the workflow has a push-to-`master` trigger for this check, and the check is not in any PR's `ci-gate` needs.
- [ ] AC-5: the delegator skill names the response procedure (gate-exception row, retro PR, user only if red, no revert).
