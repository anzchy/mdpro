## What to build

The Gate inputs are derived, not hand-kept: a scan over the test and gate-script sources lists the repo paths and prefixes they read. Any read path that classifies as `prose` is an error until it is added to the policy scope by exact path (ADR-0147 is one today). The `doc-policy` test list is the scan's output.

A `policy` PR then runs `prose-checks` and `doc-policy` (vitest without coverage over the scanned tests) and skips `frontend`, `rust-test` and `rust-audit`. `ci-gate` treats those skips as passing only when the scope job succeeded and output `policy`; otherwise it fails closed.

Spec: DCT-r1-D3 (exact paths), D4, D6; stories 7–12.

## Acceptance criteria

- [ ] AC-1 (unit, seam 2): the scan runs over the real test and gate-script sources and the test fails when any read path classifies as `prose`; it passes on the committed tree.
- [ ] AC-2 (unit, seam 2): the `doc-policy` test list equals the scan's output.
- [ ] AC-3 (unit, seam 1): every exact-path Gate input the scan finds (ADR-0147 included) classifies as `policy`.
- [ ] AC-4 (unit, seam 3): on `policy`, the workflow runs `prose-checks` and `doc-policy` and skips `frontend`, `rust-test`, `rust-audit`.
- [ ] AC-5 (unit, seam 3): `ci-gate` accepts those skips only when the scope job's result is success and its output is `policy`; a failed or missing scope output fails `ci-gate`.
- [ ] AC-6: no permanent test reads git history.
