## Best-practice findings

Severity here measures recurring reading, maintenance and decision load. It is not a product-defect severity, a merge verdict, or an allegation that the historical authors broke today's rules. ADR-0165 deliberately changed the scope after many records were accepted.

### F1 — High: process history still participates in current authority

**Evidence.** The 54 R records cover audit rounds, roster, model effort, receipts, machine admission and workflow. The current charter excludes these from new global ADRs, but old process clauses govern until folded individually ([docs/adr/README.md:17](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/README.md#L17), [docs/adr/README.md:68](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/README.md#L68)). Twenty R records have a formal Current-text annotation; its scope is only the named clauses. Another annotation is on the K charter ADR-0165 itself. The remainder includes both policies already expressed elsewhere and genuinely ADR-led procedures; lack of a marker alone is not proof that no current rule exists.

The most expensive chains are:

| Topic | Historical sources | Current operational homes and remaining seam |
|---|---|---|
| Audits, rounds, pinning and exception handling | 0115, 0118–0121, 0129, 0131, 0137, 0142–0143, 0146, 0147 | `docs/agents/auditor.md`, `docs/agents/audit-dimensions.md`, `docs/agents/audit-policy-set.md`, delegator `references/landing-and-audit.md`, and dated fold/change entries. Routing is useful; re-reading historical round counts to infer today's rule is not. |
| Roster, slots and effort | 0083–0084, 0118–0119, 0124, 0133–0141, 0156 | Rule 71 plus delegator `references/roster-and-routing.md` and `codex-panes.md`; partial forward links make it easy to confuse a superseded model name with a still-live reset obligation. |
| Test receipts and verification | 0074, 0077, 0089, 0125, 0128, 0130, 0145, 0149, 0161 | Rule 10, `docs/guide/receipt-evidence.md`, workflow/config and skill. The 0161 runtime transition is deliberately pending; an index must preserve that distinction. |
| Heavy/GUI lock admission | 0135 and 0150–0155 | Seven global records describe one developer-machine policy, with overlapping operational rules. Give current admission, stop and cleanup behavior one tooling home; keep past choices in the process log/history. |

This is a navigation/precedence burden, not a finding that every link is verbatim duplication. The D355 entry documents a concrete failure of the split: moved audit prose still said three rounds and optional Opus before being corrected to 0143 ([docs/agents/decisions/20261102-d355-rules-70-71-fold-in.md:39](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/agents/decisions/20261102-d355-rules-70-71-fold-in.md?plain=1#L39)). The partial-copy failure is stronger evidence than file count alone.

**Fix.** Start with an index showing the operational home and any surviving legacy clause. Fold the remaining clauses in coherent topic batches only when touched. Make rules answer “what applies now,” log entries answer “why it changed,” and ADRs answer durable product/architecture questions. Preserve review for actual gate changes. This matches progressive disclosure in [OpenAI's engineering account](https://openai.com/index/harness-engineering/) and scoped, noncontradictory instructions in [Anthropic's memory guidance](https://code.claude.com/docs/en/memory).

### F2 — High: there is a policy for ADRs, but no useful portfolio index

**Evidence.** `docs/adr/README.md` explains creation, statuses and immutability, ending with promotion examples; it does not list active product topics, proposals, historical decisions or process destinations ([docs/adr/README.md:7](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/README.md#L7), [docs/adr/README.md:86](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/README.md#L86)). A filename search puts obsolete round-count choices next to persistent app contracts. Even this request overcounted the numbered inventory by one.

**Fix.** Add a short topic index to that README, with links to separate proposal, history and process sections. List each K lead once, its M amendments beneath it, and any partial supersession caveat. Link to current rules for R; do not mark every R file nonbinding merely because of its classification. Keep the full classification in this audit, not in every brief or always-on read set. This is the cheapest way to reduce discovery cost while leaving history and tests intact. [adr.github.io](https://adr.github.io/) frames the records collectively as a decision log; [Nygard](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions) emphasizes small, connected records whose earlier reasoning remains available.

### F3 — High: the migration mechanism is coupled to incidental document bytes and locations

**Evidence.** Status changes are allowed, yet some tests pin substantially more than accepted decision bodies:

- `rule-citations.test.ts` requires the 0146 citation to occur at **line 49**, so inserting a permitted Status annotation above it changes the asserted result ([tests/tooling/rule-citations.test.ts:66](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/tests/tooling/rule-citations.test.ts#L66)).
- The 0147 test hashes its body and residual Status block and expects exactly two particular fold/change lines ([tests/tooling/gh586-audit-policy-split.test.ts:227](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/tests/tooling/gh586-audit-policy-split.test.ts#L227)).
- The helper strips only one particular Current-text line before other byte comparisons; it is not a general parser of allowed Status changes ([tests/tooling/d355-fix1-lib.ts:129](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/tests/tooling/d355-fix1-lib.ts#L129)).
- The resolver finds ADRs only directly under `docs/adr/` ([tests/tooling/d355-fix1-lib.ts:68](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/tests/tooling/d355-fix1-lib.ts#L68)). Another test reads every directory entry as a file: adding an `archive/` directory would itself encounter a directory read, before accounting for broken links ([tests/tooling/d355-fix1-fx2.test.ts:71](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/tests/tooling/d355-fix1-fx2.test.ts#L71)).
- 0161's whole-file bytes/forward-link state are intentionally tied to its go-live condition ([tests/tooling/d355-fix1-fx2.test.ts:60](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/tests/tooling/d355-fix1-fx2.test.ts#L60)). Do not relax this as an incidental cleanup.

**Fix.** Avoid moving files or sweeping Status now. If a later scoped fold requires a permitted metadata change, update only the relevant tooling assertion to preserve the real obligation: immutable accepted body, valid forward link, and correct transition state. Do not remove a safety check just to make reclassification green. This is a future tooling-maintenance proposal, not a product-code change in this review. The cited best-practice guidance supports historical traceability; exact line numbers are a local implementation choice, not an ADR requirement.

### F4 — Medium: several records are implementation plans, runbooks or review transcripts

**Evidence.** ADR-0147 has 8,429 whitespace-delimited words and contains routing rules, byte budgets, gardener choices, implementation work and review dispositions ([ADR-0147:180](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0147-always-on-instructions-become-a-routing-map.md#L180), [ADR-0147:437](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0147-always-on-instructions-become-a-routing-map.md#L437), [ADR-0147:547](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0147-always-on-instructions-become-a-routing-map.md#L547)). ADR-0146 has 4,469 words and combines pinning policy, audit protocol and review history ([ADR-0146:133](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0146-audits-use-project-dimensions-kept-in-the-repo.md#L133), [ADR-0146:346](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0146-audits-use-project-dimensions-kept-in-the-repo.md#L346)). ADR-0098 has 4,383 words and a long migration procedure ([ADR-0098:249](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0098-launcher-tooling-and-perf-tests-move-into-their-own-folders-under-tests.md#L249)). Even retained product records include substantial execution material: 0047 has 3,248 words; 0114 has 3,375 and many individual command/key decisions ([ADR-0047:156](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0047-agents-verify-in-the-real-app-through-a-feature-gated-control-channel.md#L156), [ADR-0114:101](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0114-the-menu-bar-and-default-keys-follow-one-command-table-and-vmark.md#L101)). These are not all one-page explanations of one consequential choice.

**Fix.** Leave accepted text intact. On the next real replacement, keep the decision, alternatives, constraints and tradeoffs in the ADR; put mutable steps in the runbook/spec and raw evidence in a test/reference record. For existing long records, the index can point to the Decision section and identify the live procedure without creating another summary authority. ADR-0114's single command-table contract is worth retaining; its entire per-command table need not become the template for every new ADR.

[Nygard](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions) recommends short records, and [Azure](https://learn.microsoft.com/en-us/azure/well-architected/architect-role/architecture-decision-record) separates the decision record from implementation design detail. This is a readability finding, not a universal word-limit violation: [Google Cloud](https://docs.cloud.google.com/architecture/architecture-decision-records) permits different lengths, and [MADR](https://adr.github.io/madr/) offers lightweight formats. mdpro already recommends a page where possible and linked evidence ([docs/adr/README.md:32](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/README.md#L32)); applying that prospectively is sufficient.

### F5 — Medium: fine-grained amendments and evidence corrections fragment product topics

**Evidence.** Thirty M records extend existing boundaries. Quit behavior has a lead plus six amendments; modal ownership has a lead plus five; watcher reconciliation has a lead plus five. Records 0008 and 0018 explicitly correct characterization while retaining the underlying decision ([ADR-0008:56](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0008-non-candidate-delimiter-class-measured-against-gfm.md#L56), [ADR-0018:3](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0018-bottom-of-document-stranded-heading-count.md#L3)). They preserve useful evidence, but future measurement corrections do not need a new global decision number when no decision changed.

**Fix.** Group first; consolidate only at the next substantive decision. Keep distinct real choices visible within the group. A later ADR may replace a coherent contract, but a single “all editor decisions” mega-record would be worse. Put future no-decision experiment corrections in a linked evidence record and a permitted dated Status note when warranted. [AWS](https://docs.aws.amazon.com/prescriptive-guidance/latest/architectural-decision-records/adr-process.html) emphasizes rationale for significant choices; [Azure](https://learn.microsoft.com/en-us/azure/well-architected/architect-role/architecture-decision-record) allows multiple records across phases. Neither requires one ADR per bug fix, nor forbids genuine incremental decisions.

### F6 — Medium: classification, acceptance and implementation status need separate meanings

**Evidence.** ADR-0010 and 0090 are Proposed; 0090 also has a partial supersession. ADR-0158 is explicitly Rejected, not a live Windows shortcut default. ADR-0166 is Accepted but says “Nothing yet” under enforcement. ADR-0162's temporary provisions expired at 0.3.6, and the D355 entry says so. ADR-0132's accepted known defect remains listed in the changelog ([ADR-0010:3](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0010-continue-vs-rewrite.md#L3), [ADR-0090:3](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0090-windows-and-linux-quit-through-the-quit-guard.md#L3), [ADR-0158:3](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0158-toggle-sidebar-defaults-to-ctrl-shift-1-on-windows.md#L3), [ADR-0166:7](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0166-mdpro-owns-macos-single-instance-admission-and-forwarding.md#L7), [docs/agents/decisions/20261102-d355-rules-70-71-fold-in.md:56](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/agents/decisions/20261102-d355-rules-70-71-fold-in.md?plain=1#L56), [CHANGELOG.md:24](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/CHANGELOG.md#L24)).

**Fix.** In the index distinguish accepted design, proposal, release-specific history, rejected/obsolete record, and current enforcement evidence. K does not mean shipped, R does not mean revoked, and S does not mean safe to delete. For uncertain implementation compliance, retain the record and file a narrow verification item; do not infer “Drifted” from age or missing tests. This avoids reducing the number by accidentally retiring a still-open data-loss acceptance.

### F7 — Medium: scope and review cost remain local policy choices, not universal best practice

**Evidence.** ADR-0165 correctly excludes process-only decisions, but explicitly includes dependencies and mixed product/process decisions. Its review trigger is broader than a generic “large decision”: a dependency or persisted key is enough ([docs/adr/README.md:11](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/README.md#L11), [docs/adr/README.md:61](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/README.md#L61)). Thus 0023's dependency refusal, 0163's fast-check choice, and 0047's verification-build/security boundary remain K. The 0165 charter is its own explicit exception. Conversely, minor future color tuning like 0110 can usually live with the item/spec/ledger under the existing below-bar route ([docs/adr/README.md:26](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/README.md#L26)).

**Fix.** Apply the current scope test before reserving a number and use the already-authorized below-bar route. Do not ask the user to choose an ADR format for every small change. Any further reduction of review triggers should be a separately justified charter change, not smuggled into this classification.

[MADR](https://adr.github.io/madr/) and [AWS](https://docs.aws.amazon.com/prescriptive-guidance/latest/architectural-decision-records/adr-process.html) allow significant tooling/process choices. Process ADRs are therefore **not inherently contrary to industry practice**; mdpro's narrower scope is a sensible local response to its workload. No cited source mandates two auditors, a global ten- or twenty-record cap, or mdpro's exact fold-in procedure. [Google Cloud](https://docs.cloud.google.com/architecture/architecture-decision-records) also treats an existing standard decision basis as a reason not to repeat the decision exercise.

### F8 — Low: keep “Enforced by” as a pointer, not another rule body

**Evidence.** The explicit new convention is visible in 0165 and 0166; this is not a widespread duplicated-list defect across all 163 files. Both honestly identify missing mechanical enforcement ([ADR-0165:38](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0165-adrs-record-architecture-and-product-decisions-only.md#L38), [ADR-0166:7](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/adr/0166-mdpro-owns-macos-single-instance-admission-and-forwarding.md#L7)). The promised universal ADR reference lint is still a follow-up, and the delegator guide currently requires manual checking ([.agents/skills/mdpro-delegator/references/guide.md:109](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/.agents/skills/mdpro-delegator/references/guide.md#L109)). Existing rule-citation tests do not establish that every arbitrary ADR reference resolves.

**Fix.** Keep a compact link to the owning test/gate/config, or a clear statement that enforcement is absent. Avoid repeating assertions, commands and reviewer checklists there. Do not backfill historical templates. A future scoped link checker should check IDs/targets and permitted status transitions, not impose literal prose everywhere. Preserve the useful distinction between a recorded decision and evidence it is implemented.

## Migration plan

### Choose index-first; defer physical consolidation

| Option | Files and dependencies | Decision |
|---|---|---|
| Index only | One existing file, `docs/adr/README.md`; optionally one linked inventory file if needed. No accepted-body changes; existing paths and hashes remain. A navigation index cannot revoke legacy clauses. | **Do first.** Cheapest useful reduction in discovery cost. |
| One process-log entry per coherent fold batch | One new immutable log entry, its current rule/reference home(s), N affected Status annotations, index updates, and any directly affected checks. D355 already demonstrates a table of several folds in one entry. | **Do as topics are touched.** Not 54 separate retrospective essays. Classify gate-sensitive changes under the existing route. |
| One new superseding charter ADR | New reserved ADR plus permitted Status links, charter/rules/guide updates, and policy tests/review. Needed if changing authority or inventing a new bulk-retirement rule beyond 0165. | **Optional, not prerequisite.** Do not create another governance project merely to get an index. It cannot coherently replace all product decisions. |
| Bulk “Superseded” / “Retired” sweep | Up to 100 R/S/M statuses plus successor/log and tests. “Retired” is not an allowed status; “Superseded by ADR-NNNN” requires an actual applicable replacement. R fold-in explicitly keeps Accepted. | **Reject as the first step.** Semantic and test cost exceeds navigation benefit. |
| Move old records to `docs/adr/archive/` | Up to 100 file moves, inbound/outbound links, flat-directory readers, protected text/path checks, ledger and historical references. Relative links can change meaning after moving. | **Do not do.** No need to change location to label history; even adding the directory conflicts with a current reader. |
| Formal product-topic consolidation | One new ADR per genuinely revised coherent contract, status links on its lead/amendments, updated referring specs/ledger where necessary, relevant checks/review. | **Opportunistic later work.** Do not rewrite accepted bodies or consolidate unrelated choices for a numerical goal. |

Accepted-body immutability itself is well supported by [Azure](https://learn.microsoft.com/en-us/azure/well-architected/architect-role/architecture-decision-record) and [AWS](https://docs.aws.amazon.com/prescriptive-guidance/latest/architectural-decision-records/adr-process.html). The extra cost is clause-by-clause authority transfer combined with metadata-specific tests. The existing [process-clause change entry](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/docs/agents/decisions/20261102-changing-an-unfolded-process-adr-clause.md#L4) already permits fold-and-change without a new global ADR for legacy process records; use that route before inventing another.

### Small, reviewable commits

1. **Publish the audit and track the proposal.** This report and its GitHub issue are advisory. No live rule changes, no accepted-body changes, no mass status updates. The user's follow-up authorizes these deliverables, not the later policy migrations.
2. **Add the topic index.** Edit only `docs/adr/README.md` where practical. Include all 163 IDs exactly once in the disposition inventory, 63 clearly labeled leads, and links for every M source, S successor/evidence and R current home/unfolded caveat. Preserve all existing charter text. Verify count, uniqueness, links and anchors; do not add a mandatory “read all ADRs” instruction.
3. **Pilot one narrowly bounded process fold.** Choose one already well-understood rule/reference home, not the pending 0161 go-live. Write one log entry identifying exact clauses, unchanged versus changed text, and destinations; move the operational text and add the allowed Status pointers in the same commit. Resolve any affected assertion narrowly. The pilot succeeds when a reader can determine the current rule from that home without reconstructing a historical chain.
4. **Repeat by operational topic only when useful.** Candidate batches are receipt evidence, roster/effort, and heavy-lock policy. Keep gate changes separate from mechanical moves; preserve protected audit-policy review and runtime-transition prerequisites. One topic can require several small commits if its clauses have different owners or activation conditions. Do not manufacture retrospective decision entries for settled history.
5. **Consolidate a product topic at its next genuine revision.** For example, quit handling would eventually have one replacement plus Status pointers on 0025 and its six M amendments (at least eight ADR files touched, before references). Reserve the new number through the normal route; do not assume the next free number. Carry each surviving safety constraint and explicit supersession scope. The index then routes to the replacement.
6. **Stop when navigation and authority are clear.** No obligation to migrate every historical file. Recheck an index entry when it is touched; do not create a standing full-portfolio review ceremony.

### Verification and dependencies

This review executed no build, product test, GUI test, or policy test. Its checks were inventory/count reconciliation, source inspection, citation/path checks and comparison with primary guidance. Future migration validation should match the actual changed files:

- **Index-only:** check unique IDs, live link/anchor targets and immutable-source diff. Run the repository's required documentation checks for the landing route. The existing `rule-citations` scanner covers tracked Markdown and rules 70/71 citations; avoid making an index into a duplicate policy statement ([tests/tooling/rule-citations-lib.ts:188](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/tests/tooling/rule-citations-lib.ts#L188)). It is not a general all-ADR link checker.
- **Rule/reference fold:** run the relevant `rule-citations`, `always-on-budget`, D355 and GH586 tests through `scripts/heavy-lock.sh` as required by the repository. The always-on budget measures mandatory routed reads, not the sum of every ADR's bytes ([tests/tooling/always-on-budget.test.ts:212](https://github.com/anzchy/mdpro/blob/8706fae66440c10dc847178988219f0dbae70928/tests/tooling/always-on-budget.test.ts#L212)). An index should remain discoverable without becoming a required session read.
- **Status-only changes:** inspect the specific ADR's byte/line pins before editing. Preserve 0161's separate go-live proof. Do not disable protected-policy assertions globally.
- **Ledger or path changes:** inspect inbound Markdown/code/config references first. Existing feature-ledger links name ADR paths; run `pnpm ledger:check` when the ledger is affected and regenerate its derived output only if its source changes. The ledger path checker is not a substitute for checking all Markdown links. Index-only work needs no ledger rewrite.
- **Charter or gate semantics:** follow the actual plan-review/approval route and its policy checks. This advisory classification supplies evidence, not acceptance of a revised gate.

No wholesale old-record template migration, no renumbering, no archive directory, and no product-code edits are needed to obtain the first benefit.
