### F1：WYSIWYG 编辑后，分隔线 `---` 被写成 `***`（[D79](../plans/20260912-frontend-backend-sequencing-order.md#d79)，NOTE）

D72 里 store 的末尾是 `***`，而文件原文是 `---`。这不是 D72 的回退引起的：分隔线节点完好（画着，`Z` 落在它前面），是整篇重新序列化时的规范化。原因在依赖的默认值，不是 mdpro 的代码：Milkdown 的 `hr` 节点序列化成 mdast 的 `thematicBreak`（`@milkdown/preset-commonmark` `src/node/hr.ts:30`，原标记不记录），`mdast-util-to-markdown` 写 `thematicBreak` 时用 `options.rule || '*'`（2.1.2 `lib/util/check-rule.js:10`），重复 3 次。mdpro 唯一一处改 `remarkStringifyOptionsCtx` 的是 `src/plugins/milkdown/highlightMarkPlugin.ts:133-142`，只加了一个 `highlight` handler，没有设 `rule`；`git log -G"rule: ['\"]" -- src` 与 `-S ruleRepetition` 都是空的，从来没设过。所以这是 WYSIWYG 自引入 Milkdown 起就有的行为，不是本轮的回归。

查过的文档里都没写：功能台账、`docs/adr/`（没有关于 Markdown 往返保真的 ADR）、各次真机记录、`progress.md` 都没有 `***` / thematicBreak 规范化的记载；序列文档里也没有对应的 D 行（D64 与 D44 只涉及表格的序列化）。后果只是外观：语义不变、不丢内容，但任何一次 WYSIWYG 编辑后保存，文件里每条 `---` 都会变成 `***`，用 git 管理的笔记会出现与本次编辑无关的 diff。改法若只是设 `rule: '-'`，会改变所有 WYSIWYG 输出，要不要做、要不要一并处理其他标记的规范化，属于往返保真的取舍，值得先登记再定。

### F2：外部打开被退出守卫拒绝后，日志仍记一条 `file.open.external` `success`（[D80](../plans/20260912-frontend-backend-sequencing-order.md#d80)，SHOULD）
