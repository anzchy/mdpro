# Card D261: Windows menu actions stay with their clicked window and document

**Controlling AC** ([D261](../../plans/20260912-frontend-backend-sequencing-order.md#d261), quoted):

> **真机待验**（菜单批次）：两窗口只一个执行；点击后焦点移动；无聚焦窗口时的 `last_focused` / `any_live` / `no_focused_window`；Windows 菜单栏保持其窗口的焦点；Table + 切换、Highlight、Save As + 切换、关闭确认 + 切换。

This Windows card narrows the quoted AC to the cases Windows can exercise. A Windows window owns its own menu bar, so the macOS-only no-focused-window fallback case is **平台不适用**, not a PASS.

## Setup

- Use the `mdpro-windows-<version>-dev-<sha7>` artifact produced by `build-windows.yml` from current `master`. Record the workflow run and full `head_sha`, installer and installed-executable SHA-256, and confirm the first `app.ready` after launch has `releaseId:"<version>-dev@<full head_sha>"`. `releaseId:"unknown"` stops the card.
- Use the remote Windows driver only. Maximize after launch; record the display scale (expected on `win-desktop`: 270%) and `innerWidth` (about 1120 or greater).
- With mdpro closed, snapshot preferences/drafts and push two scratch copies of `tests/manual-fixtures/d37-small-doc.md` under `%WIN_DIR%\fx\w036\` as `d261-a.md` and `d261-b.md`; then, before launch, snapshot the complete directory-entry listing there. Reserve and record a Save As output path `P` that is absent from the snapshot; if it already exists, stop before launch rather than overwrite it. Never open a user document.
- Then open two restored, non-overlapping windows A and B, one fixture per window. Restore the snapshot and both fixture bytes afterward while mdpro is closed, and remove `P` only if this run created it.

## Steps

1. `cli` — Mark the log, then use one labelled `ui.sh` `menuclick` on A for File → Save after dirtying only A. This reaches `src-tauri/src/menu.rs:366` and the single-target dispatcher at `src-tauri/src/menu_target.rs:148`. Proof: exactly one `menu.action.dispatch` success line (emitted at `src-tauri/src/menu_target.rs:204`) names A as `target`, followed by A's `ui.menu.select`/`file.save`; A becomes clean and its fixture bytes change, while B and its bytes do not.
2. `cli` — Select text in A, then invoke Format → Highlight with `menuclick` on A immediately followed by `focus` B in the **same** labelled `ui.sh` run, with no wait; repeat at least three times with undo/reset between attempts. The receiver checks the addressed label at `src/hooks/useMenuEvents.ts:103`; a mismatch is logged at `src/hooks/useMenuEvents.ts:107`. Proof: each click has one `menu.action.dispatch`; A alone gains one highlight mark and B's document remains byte-identical. Record whether B actually acquired focus before dispatch. If the timestamps do not force that ordering, report this subcase **NOT EXERCISED**, as W-1a did, rather than PASS.
3. `cli` — In A open Format → Insert Table by labelled `menuclick`, then use the driver `open` operation to switch A to another fixture before submitting Insert through CDP. The final mutation checks the token at `src/utils/menuTargetToken.ts:74`. Proof: `ui.menu.select` is `cancel` with `reason:"stale"` and `stage:"table_submit"` (shape at `src/utils/menuTargetToken.ts:80`); neither document gains a table.
4. `cli` — Start File → Save As… from A, switch A to another document before completing the native dialog to the reserved new path `P`, then repeat by cancelling the dialog; separately open an unsaved Close prompt before switching documents. The Save As native action is `file.save_as` at `src-tauri/src/menu.rs:367`; its positive route proof is one `menu.action.dispatch` success (event at `src-tauri/src/menu_target.rs:204`) whose context at `src-tauri/src/menu_target.rs:207` names `action:"file.save_as"` and `target:A`, followed by `ui.menu.select` success (event at `src/services/loggingService.ts:98`) with `controlId:"menu.file.save_as"` from `src/hooks/menuActionTable.ts:138`. For the same action ID, require `file.save` success at `src-tauri/src/commands/file.rs:1686` with `filePath:P` at `src-tauri/src/commands/file.rs:1691`, plus `file.save_as` success at `src-tauri/src/commands/save_as_watch.rs:117` and `src-tauri/src/commands/save_as_watch.rs:118`. Pair those lines with `bytes(P) == bytes(A at Save As entry)`, A's old path unchanged, and the switched-to document byte-identical; require no `ui.menu.select` cancel with `reason:"stale"` and `stage:"save_entry"`. Cancellation writes no new file and changes neither document. The separate close-confirm path retains the `ui.menu.select` stale-cancel proof with `reason:"stale"` and `stage:"close_confirm"`, paired with neither document or tab being closed. The entry token is captured at `src/utils/menuTargetToken.ts:53`, Save As checks it only on entry at `src/utils/menuTargetToken.ts:135`, and the close guard rechecks at `src/utils/menuTargetToken.ts:108`. If the native dialog prevents switching on Windows, record only the Save As + switch subcase **平台不适用**; the close-confirm subcase remains required.
5. `cli` — Capture the log and close every test window normally. While mdpro is closed, restore both fixture files and the configuration snapshot per `.agents/skills/remote-windows-device-test/reference/config-isolation.md:48`; if step 4 created `P` and the pre-run inventory proved it absent, delete exactly `P` and verify it is absent. Never delete an unrecorded addition: if the final directory-entry listing differs from the snapshot, preserve the unexplained path and stop for triage. Run `mdpro.sh normal --yes` only under the tester's cleared restart, then `mdpro.sh cleanup` per `.agents/skills/remote-windows-device-test/SKILL.md:133`. Proof: each window has a `window.close` line emitted at `src-tauri/src/main.rs:327` and visibly disappears; cleanup reports no scheduled task; fixture/configuration hashes equal their pre-run values; `P` is absent; and the final directory listing equals its snapshot.

## Failure condition

Fail if one click produces more than one dispatch, a non-clicked window acts, the Save As positive route or save-success lines are missing, a switched-to document is mutated or closed, Save As emits a stale `save_entry` cancellation, close-confirm omits its required stale cancellation, `P` remains after cleanup, the final directory listing differs from its snapshot, cleanup would need to delete an unrecorded addition, any other required log/effect pair is missing, or the build identity is not the locked `master` artifact. A driver failure or an unforced focus ordering is NOT EXERCISED, not product FAIL.
