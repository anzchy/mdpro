# Card D264: German AltGr characters survive the Windows editor keymaps

**Controlling AC** ([D264](../../plans/20260912-frontend-backend-sequencing-order.md#d264), quoted):

> Source 加一个非 Mac 的高优先级 AltGr 保护，`Ctrl+Alt+<与基键不同的可打印字符>` 直接作为输入，以后新加的 Ctrl-Alt 绑定也回退不了它。测试：组合后的 Source keymap，`ctrlKey+altKey`、`key` 为 `[ ] \ { @` 时不运行任何命令、不阻止默认行为。真机：Windows 菜单批次，德语 QWERTZ。

## Setup

- Use the current-master `build-windows.yml` development artifact. Record the workflow `head_sha`, installer/executable hashes, and launch `app.ready.releaseId == <version>-dev@<full head_sha>`. Record display scale (expected 270%) and maximize to about 1120 CSS px or wider.
- With mdpro closed, copy `tests/manual-fixtures/d37-small-doc.md` to `%WIN_DIR%\fx\w036\d264.md`, record its hash, and snapshot preferences, drafts, and `Get-WinUserLanguageList` to an export outside the repo.
- Add `de-DE` with `Set-WinUserLanguageList`, activate its `00000407` layout for the mdpro target thread, and verify with the driver's labelled `layout` op. This setting change must be removed/restored in cleanup even after a failed product step.

## Steps

1. `cli` — Focus the Source editor with a real `clickat`; immediately read the target window HKL with labelled `layout`. The driver contract requires that exact HKL for physical input, and the guard is installed on Source at `src/components/Editor/Editor.tsx:229`. Proof: driver output reports the de-DE HKL and the Source surface is active; otherwise stop as NOT EXERCISED.
2. `cli` — For each expected German QWERTZ output, send the corresponding labelled `physicalChord` with the exact HKL from step 1: `AltRight+Digit8` → `[`, `AltRight+Digit9` → `]`, `AltRight+Minus` → `\\`, `AltRight+Digit7` → `{`, and `AltRight+KeyQ` → `@`. The guard identifies printable AltGr at `src/plugins/codemirror/altGrGuard.ts:13` and stops editor keymaps without preventing text input at `src/plugins/codemirror/altGrGuard.ts:20`. Proof for every character: it appears once in the Source document, no `ui.editor.command` or `ui.shortcut.trigger` line is emitted, and the captured key event is not default-prevented.
3. `cli` — On the same physical-input route send a real non-AltGr Source command as the passing control. The Source keymap integration is at `src/plugins/codemirror/sourceFormatPlugin.ts:72`. Proof: the control emits its expected command log/effect and can be undone once. Without the control, an apparent AltGr failure is NOT EXERCISED.
4. `cli` — Save the scratch file through a real Ctrl+S and inspect its bytes. The save shortcut path is `src/hooks/useKeyboardShortcuts.ts:143`. Proof: `ui.shortcut.trigger` and `file.save` success pair with UTF-8 bytes containing the five Source characters exactly once.
5. `cli` — Close mdpro normally. Restore the exported language list exactly (removing `de-DE` when it was absent before), restore configuration/drafts and fixture bytes while mdpro is closed per `.agents/skills/remote-windows-device-test/reference/config-isolation.md:48`, confirm the language list and hashes equal their pre-run values, return mdpro to normal mode, and run cleanup per `.agents/skills/remote-windows-device-test/SKILL.md:133`. Proof: `window.close` emitted at `src-tauri/src/main.rs:327` pairs with the window visibly disappearing; cleanup succeeds and the language list/hashes equal their pre-run values.

## Failure condition

Fail if any of `[ ] \\ { @` is swallowed, transformed, duplicated, default-prevented, or dispatches an editor/app command while the de-DE HKL and same-route control are proven. A layout/HKL mismatch, uncertain physical injection, or absent control is NOT EXERCISED, not product FAIL.
