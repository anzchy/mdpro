# MIG-002 row a: Save and Save As on macOS

**Controlling AC:** [MIG-002a2 (#736)](https://github.com/anzchy/mdpro/issues/736), approved spec r3 § Device AC. Covers a1's a-C2/a-C4/a-CS and a2's a-C1/a-C3/a-C5/a-C6/a-C7/a-C8/a-C9. Run in the single M0 Mac batch at the master SHA after the final MIG-002 sub-PR. The per-PR departure from ADR-0144 decisions 3 and 6 uses the recorded decision-5 waiver quoting 「Keep #686, name departure (Recommended)」; the delegator names this card in round-one audit.

## Setup

- **[cli]** Acquire the shared Mac GUI lock, build the exact candidate SHA, and copy `tests/manual-fixtures/` documents to a writable scratch directory. Record SHA, app version, fixture checksums, `~/.mdpro/mdpro.log` start offset and a screen recording. **Proof:** command transcript and checksums. **Failure:** wrong SHA, shared lock unavailable or source fixtures modified. **Log/effect:** startup `app.*` lines identify the run; the scratch files, never the fixtures, receive writes.
- **[computer-use]** Open the scratch document in the built app and leave auto-save disabled. Keep one clean copy for byte comparison. **Proof:** active tab/path screenshot and disk hash. **Failure:** wrong document or an unsolicited write. **Log/effect:** `file.open` success and unchanged scratch bytes.

## Scenarios

1. **Immediate Cmd+S after typing (a-C2).** **[computer-use]** Type a unique `X`, immediately press Cmd+S before the edit-sync delay, then inspect the tab and scratch file. **Proof:** screen recording timestamps and exact UTF-8 bytes. **Failure:** missing `X`, false clean state, duplicate/older write. **Log/effect:** `file.save` success for that document and a clean tab only after the file contains `X`.
2. **Save while typing continues, including failure (a-C1/a-C3/a-C4/a-CS).** **[human]** On a large scratch document, type `A`, initiate Save, continue with `B` while it is in flight, then save again; repeat after inducing an unwritable destination or other real save error. **Proof:** screen recording, ordered file bytes, dirty indicator and log sequence. **Failure:** old bytes land after new bytes, `B` disappears, failed write reports Saved, or dirty state clears before `B` persists. **Log/effect:** queued/success/fail `file.save` lines match ordered writes; the error leaves the buffer dirty. Do not use a synthetic serializer fault on the device; the App journey owns a-CS and a-KL1.
3. **Save As to a new path, then save (a-C7).** **[computer-use]** Choose File → Save As, use the native macOS save panel to select a fresh scratch path, edit, then Cmd+S. **Proof:** panel recording, two target hashes and old-path hash. **Failure:** panel does not appear, later Save writes the old path, or the old file changes. **Log/effect:** `save_file_dialog` outcome then `file.save` success; document tab follows the target path and the old file bytes stay unchanged.
4. **Save As onto a path already open in another tab (a-C7).** **[computer-use]** Open two different scratch documents, edit the first, then select the second's path in the native Save As panel. **Proof:** panel/result recording, both tab states and before/after hashes. **Failure:** silent overwrite of the second file or either tab falsely marked clean. **Log/effect:** save refusal/failure line and no destination write; the original buffer remains dirty.
5. **Second-window notice while this window is dirty (a-C8).** **[computer-use]** Open the same scratch path in two mdpro windows, edit window A without saving, then save a different edit in window B. Return focus to A. **Proof:** both window labels/screens, A's unsaved text and prompt, disk hash, ordered notice lines. **Failure:** A's dirty buffer overwritten or B's own save treated as an external conflict. **Log/effect:** `file.save.notice` carries B origin; A gets `file.change.received` scheduled/delivered; B records `own-save`. The notice does not write A's buffer.
6. **Pinyin composition and Cmd+S (a-C9).** **[human]** Enable macOS Pinyin, begin composing `亲爱的` in a copied category-l CJK document, press Cmd+S before confirming the candidate, confirm it, then save again. **Proof:** screen recording showing marked composition, key event order and exact UTF-8 bytes of both saves. **Failure:** dropped, duplicated or replacement-character text, a false clean state, or a failed flush reported as success. **Log/effect:** `file.save` lines and the disk bytes capture today's composition outcome; the second save contains the confirmed text.

## Lifecycle and external-change checks

- **[computer-use]** During a save, close/reopen the tab, then repeat with a reload and a Save As path move (a-C5). **Proof:** screen recording, tab content and before/after hashes. **Failure:** a stale completion cleans or rebaselines the newer buffer. **Log/effect:** stale-cancel or demotion line corresponds to the old task; the replacement stays dirty when appropriate. a-KL2/#787 pins today's stale-result failure after write start; record it as FAIL until the ADR-0146 disposition and fix.
- **[computer-use]** Change the scratch file outside mdpro before Save; repeat after deletion and choose Cancel, then an explicit recreate (a-C6). **Proof:** prompt screenshots, disk hashes and dirty indicators. **Failure:** write before consent, lost ignored-deletion marker, or stale consent accepted. **Log/effect:** `file.change.received` and save-blocked/recreate-choice lines track the prompt; no write precedes the matching choice.

## Result record

Record PASS/FAIL/NOT RUN for each scenario, the exact candidate SHA, device/OS/input method, timestamps, video and log paths, before/after hashes, and any deviation. A missing native panel, true second-window focus or Pinyin OS key sequence is NOT RUN rather than inferred from jsdom. The three ADR-0144 platform entries are **native dialog**, **cross-window focus**, and **OS key event**.
