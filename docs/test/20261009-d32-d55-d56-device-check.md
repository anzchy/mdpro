**Reading.** The false prompt comes from LaunchServices, not from mdpro. An external `open -a … b.md` while `b.md` is already open and watched (in W2) makes LaunchServices rewrite `b.md`'s `com.apple.lastuseddate#PS` xattr. Its value changed to `83 65 C8 6A …` = 0x6AC86583 = 1791518083 = 11:54:43, the R6 open time. FSEvents reports this as `modify_metadata`. The watcher emits it as `emitted_modified`, although mtime and size equal B0, and W2 shows a `reload-prompt` on a clean doc.

The brief's R3/R5 scenario (an external open of *another* file, `a.md`) did **not** reproduce. In this run `a.md` was never watched (H2), so its xattr stamp produced no event. A prompt from an open of "another file" would need that other file to be watched, and to be the same file as the clean one that prompts. In this run the trigger was a re-open of the prompting file itself. R2 (the first open of `b.md`) did not prompt, because the LaunchServices stamp happened before `file.watch.register` (L8524).
