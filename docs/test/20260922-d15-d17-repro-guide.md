# D15 / D16 / D17 复现指南（2026-09-22）

**用途**：交给一个没有本仓库上下文的执行者（Codex 或人）独立复现三条缺陷。执行者要回答的问题是：**它是真的吗？在哪些条件下出现？** 修不修不归执行者管。

三条缺陷都来自 D14 真机验收，原始观察记在 `docs/test/20260922-d14-gui-acceptance.md`，状态行在 `docs/plans/20260912-frontend-backend-sequencing-order.md` 的 D15、D16、D17 三行。

**执行者须遵守**：

1. **只复现、只记录**。不改 `src/`、`src-tauri/`、`tests/`，不 commit，不 push。
2. **别碰用户的真实文档**。只在下文 §1.3 生成的夹具副本上操作；每次复现开始前重新复制一份。
3. **每一步都记下输入方式**：是实体键盘，还是合成事件（computer-use、AppleScript `keystroke`、CGEvent）；当时的输入法是哪一个。D15 已经证明，这两件事会左右结论。
4. **一个判据只有三种结论**：`REPRODUCED`（复现了）、`NOT REPRODUCED`（按步骤做了，没出现）、`BLOCKED`（因为某个原因做不了，写明原因）。「看起来好像」不算结论。

### 1.3 夹具

在仓库之外生成夹具：一篇 12 个 `##` 标题、每节 15 段的文档，不带 frontmatter。

```bash
mkdir -p ~/mdpro-repro && cd ~/mdpro-repro
python3 - <<'EOF'
lorem = "Lorem ipsum dolor sit amet consectetur adipiscing elit sed do eiusmod tempor incididunt ut labore et dolore magna aliqua."
for name in ("a", "b"):
    L = [f"# Repro fixture {name.upper()}", ""]
    for h in range(1, 13):
        L += [f"## {name.upper()} H{h:02}", ""]
        for p in range(1, 16):
            L += [f"{name.upper()}-H{h:02}-P{p:02} {lorem}", ""]
    open(f"repro-{name}.src.md", "w").write("\n".join(L))
EOF
cp repro-a.src.md repro-a.md && cp repro-b.src.md repro-b.md
shasum repro-a.md repro-b.md
```

每个判据开始前都执行一次 `cp repro-a.src.md repro-a.md`，保证从同一份原文开始。

## 2. D15：在 WYSIWYG 里打的字，显示了却不进文档（候选 BLOCK，涉及数据丢失）

### 2.1 已观察到的现象

- 在 WYSIWYG 里往段落或标题里打字，屏幕上能看到字，光标也在字后面。
- 但 4 秒后标签页上没有脏标记，大纲没有更新。
- 按 ⌃2 切到源码，文字不在；再按 ⌃4 切回来，WYSIWYG 里的字也没了。
- 按 ⌘S 保存，写出的文件里没有这些字母，只多了一个孤立的 `\xa0`。
- 日志里没有任何内容事件或文件事件。

观察时的条件：

- 输入全部是 **computer-use 合成的 CGEvent**，输入法 WeType 拼音与 ABC 都试过，现象一样。
- 构建 `00842dd` 和对照 `c9a1698` 都出现。
- **还没有用实体键盘试过。**

### 2.2 候选机制（读代码得出，**尚未验证**，请执行者证实或推翻）

问题在 `src/components/Editor/MilkdownEditor.tsx:180-216`：

- 登记 `markdownUpdated` 监听的 effect，依赖是 `[editor, activeDocumentId]`。
- `@milkdown/react` 的 `useEditor` 每次渲染都返回一个**新对象** `{loading, get}`，见 `node_modules/@milkdown/react/lib/index.js:56-66`，所以这个 effect 每次渲染都会重跑。
- 重跑时，React 先执行上一轮的 cleanup，它把 `disposed` 设成 `true`。
- 接着新一轮的 effect 发现 `instance === registeredInstanceRef.current`，直接 `return`，**没有重新登记监听**。
- 于是，登记之后只要 `MilkdownEditorInner` 再渲染一次，监听器就永久失效。之后的编辑都停在 ProseMirror 里，进不了 `documentStore`。

它会重渲染的原因：`MilkdownEditorInner` 订阅了 `useDocumentStore((s) => s.documents)`（第 108 行），第一次编辑写进 store 就会触发重渲染。

**如果这个机制成立，就应该看到**：**第一批**编辑能进 store（因为监听有 200 ms 防抖，这一批是 200 ms 内的连续输入），之后的全部丢失。已有两条日志与此吻合：

- 对照构建上 `contentLength` 只变了一次（16248→16152），之后再没变过；
- 2026-09-20 那次唯一成功的编辑只有 1 个字符（5254→5255）。

这段代码最后一次改动在 `96aff65`（2026-06-25）。

### 2.3 复现步骤

先用实体键盘做一遍；如果执行者只能用合成输入，就在同样的步骤下做一遍，结论注明「仅合成输入」。

| # | 步骤 | 记录什么 |
|---|---|---|
| R1 | 冷启动 app，打开 `repro-a.md`，确认在 WYSIWYG（⌃4）。起点行号 | 输入方式与输入法 |
| R2 | 点击 `A-H01-P01` 这一行的末尾，打一个字符 `x`，**等 2 秒** | 标签页有没有出现脏标记 |
| R3 | 接着打 `yz`，等 2 秒 | 脏标记状态有没有变化 |
| R4 | 按 ⌃2 | 源码里 `A-H01-P01` 这一行的结尾是 `x`、`xyz`，还是都没有 |
| R5 | 按 ⌃4 回到 WYSIWYG，按 ⌘S | `/usr/bin/grep -c 'A-H01-P01' repro-a.md`，以及该行末尾实际写进去的内容（`/usr/bin/grep 'A-H01-P01' repro-a.md \| cat -A`） |
| R6 | 冷启动一次，先不打字，把光标所在的节**滚动**一下，或者点一下大纲里的某一条，然后再打 `q` | 同 R4：源码里有没有 `q`（检验「打字前的任何重渲染就能让监听失效」） |
| R7 | 重复 R1–R4，但在源码模式里打字，然后 ⌃4 | 对照组：源码路径应该正常 |

**判读**：

- R4 显示 `x` 而没有 `yz`：D15 **REPRODUCED**，而且支持 §2.2 的机制。
- R4 一个字符都没有：D15 **REPRODUCED**，但机制可能不同。请看 R6，并补一次 DevTools 取证（§2.4）。
- R4 显示 `xyz`，R5 写进了文件：D15 在这种输入方式下 **NOT REPRODUCED**。如果用的是实体键盘，那么 D15 很可能是合成输入造成的假象。

### 2.4 DevTools 取证（`pnpm tauri dev`，可选但很有决定性）

在 WYSIWYG 里打几个字，然后在控制台执行：

```js

document.querySelector('.ProseMirror').innerText.includes('xyz')
// 2) store 里有没有这些字（documentStore 是否挂在 window 上取决于构建；拿不到就改看日志里的 contentLength）
```

在 `MilkdownEditor.tsx` 第 195 行的回调里临时加一个断点（dev 模式下可以直接在 Sources 面板里打），看它在第二次输入时还会不会进来，以及进来时 `disposed` 是不是 `true`。**断点只在本地打，不要提交任何改动。**

### 2.5 附带边角（低优先级，顺手记录即可）

用拼音输入法打字，**不提交组合态**（候选框还开着）就按 ⌃2，未提交的文字会丢失。这是切模式时销毁编辑器造成的，一般用户会先提交再切。只记录能否复现即可。

## 3. D16：有未保存改动时退出，没有未保存提示（候选 BLOCK）

### 3.1 已观察到的现象

- 条件：文档是脏的（在源码里改过一个标题，标签页上有脏标记）。
- 用 AppleScript `quit` 退出：app 直接退了，没有提示，也没有写文件；日志里没有 `app.quit`。
- ⌘Q 和菜单里的 Quit **没有测过**。

### 3.2 相关代码（供判断走的是哪条路径）

- 退出菜单项是系统预置的 `PredefinedMenuItem::quit`，在 `src-tauri/src/menu.rs:126`，底层是 NSApp `terminate:`。
- Rust 端的 `RunEvent::ExitRequested`（`src-tauri/src/main.rs:542`）只写一条 `app.quit` 日志并关掉 MCP 服务，**没有 `prevent_exit`**。
- 未保存守卫只挂在窗口关闭上：`src/App.tsx:390` 的 `onCloseRequested`，加上 `src/utils/dataLossGuards.ts`。
- 候选推断（**未验证**）：app 级退出不经过窗口关闭守卫，所以 ⌘Q 很可能同样不提示。

### 3.3 复现步骤

每一行都从同一个前提开始：`cp repro-a.src.md repro-a.md`，打开它，**在源码模式里**改一处（把 `## A H02` 改成 `## A H02 dirty`），确认标签页出现脏标记。用源码改，是为了避开 D15。

| # | 退出方式 | 记录什么 |
|---|---|---|
| Q1 | 点窗口左上角红色关闭按钮 | 有没有提示；选「不保存」后文件是否不变（`shasum`）；日志里有没有 `window.close` |
| Q2 | ⌘W | 同上 |
| Q3 | ⌘Q | 有没有提示；app 是否退出；`repro-a.md` 的 `shasum` 是否不变；日志里有没有 `app.quit` |
| Q4 | 菜单 mdpro → Quit mdpro | 同 Q3 |
| Q5 | `osascript -e 'tell application "mdpro" to quit'` | 同 Q3 |
| Q6 | Dock 图标右键 → 退出 | 同 Q3 |
| Q7 | 关机或注销时的退出（**可选，只在执行者被明确允许时做**） | 同 Q3 |

**判读**：

- 任何一种退出方式在有脏文档时**不提示就退出**，都算 D16 **REPRODUCED**，并写明是哪几种方式。
- 如果 Q1、Q2 提示而 Q3–Q6 不提示，就支持 §3.2 的推断。
- 退出后**重新打开 app**，看有没有草稿恢复提示（`save_draft` 自动保存）。有，说明改动还能找回，严重程度降一级；没有，就是真的丢失。

## 4. D17：切模式恢复滚动后，如果落在一节中间，大纲高亮停在 H01（SHOULD）

### 4.1 已观察到的现象

- 在 WYSIWYG 里滚到某一节的中间，按 ⌃2 再按 ⌃4。
- WI-8 把位置恢复得是对的，但大纲高亮停在 H01。
- 3 次试都是这样；如果恢复后判定带（视口上方约 34%）里正好有一个标题，高亮就是对的。

### 4.2 候选机制（推断，未打点验证）

1. `src/hooks/useWysiwygScrollSpy.ts` 的 IntersectionObserver，在新建的 Milkdown 视图 scrollTop=0 时装好，此时 H01 在判定带里，成为活动项。
2. 随后 `src/hooks/useMilkdownScrollRestore.ts` 把视图恢复到节中间，H01 离开了判定带，但没有别的标题进来。
3. 可见集合为空时，规则是「保留上一个活动项」，于是一直保着 H01。
4. 同一个局限的另一种表现：在长节里**向上**滚，标题已经在判定带上方了，高亮却停在下一条标题上。

### 4.3 复现步骤

| # | 步骤 | 记录什么 |
|---|---|---|
| S1 | 打开 `repro-a.md`，进 WYSIWYG，窗口 1200×800 | 窗口尺寸 |
| S2 | 滚动到 `A-H06-P08` 大致位于视口顶部的位置，此时判定带里**没有**标题。等 1 秒 | 大纲高亮当前在哪一条（应该是 A H06） |
| S3 | ⌃2，等 1 秒，再 ⌃4，等 1 秒 | 视口顶部是哪一段（WI-8 应恢复到 `A-H06-P08` 前后）；**大纲高亮在哪一条** |
| S4 | 重复 S2–S3 三次，每次换一节（H03、H09、H11） | 每次高亮落在哪一条 |
| S5 | 对照：滚到 `## A H07` 标题正好在视口上部 1/3 以内，再做 ⌃2 → ⌃4 | 高亮应当是 A H07 |
| S6 | 变体：在 `## A H06` 这一节里，从 P15 慢慢**向上**滚到 P05 | 高亮是 A H06 还是 A H07 |

**判读**：S3、S4 里高亮是 H01（或其他不对的条目）而 S5 正确，就是 D17 **REPRODUCED**。S6 里高亮是 A H07，属于同一局限的另一种表现，一并记录。

可选取证（`pnpm tauri dev` 控制台）：⌃4 之后立刻执行

```js
document.querySelector('.milkdown').scrollTop
```

并记录大纲里 `aria-current` 或高亮样式所在的那一条，用来确认高亮是在 scrollTop 恢复**之前**就定下来的。
