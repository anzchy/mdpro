功能账簿

mdpro · 首次建账 2026-09-17 · 分支 master（2026-10-12 前为 frontend-backend-redesign）

一份文档，两个任务。

  • 逐条查验。 Part 1 是 mdpro 声称拥有的每一项能力、它实际处在什么状态、代码在哪、以及怎么在跑着的 app 里确认它。它是写来对着 app 从头走到尾的。
  • 找出缺口。 Part 2 和 Part 3 把 mdpro 摆在另外十个编辑器旁边，明说什么是缺的、什么是故意不做的、什么是别人都没有的。

这份账簿描述 mdpro 现在有什么。它不是 changelog：一个缺陷的修复是一次提交，不是一行；给每个缺陷开一行，这份文档就没人能读了。它也不是计划：工作项的先后与验收在 docs/plans/，决策在 docs/adr/，什么时候变的在 CHANGELOG.md。

状态图例

状态是下面五个词之一，而这个区分正是本文的全部意义：

Stub 不是功能。这份账簿写 Stub 的地方，就不要对外描述 mdpro「有」这个东西。

枚举是封闭的。Shipped（仅导出） 不是一种细微差别，是一次失败——pnpm ledger:check 会因此拒绝整份文档。细微差别写进「怎么确认」那一格。

Partial 必须在「怎么确认」里带一条 限制：，写明那条限制是什么。不写明限制的 Partial，正是这条规则要挡住的东西。

怎么写「在哪」这一格

路径一律从仓库根写起，放在反引号里：src/plugins/milkdown/imagePastePlugin.ts，不是 imagePastePlugin.ts，也不是 milkdown/imagePastePlugin.ts。

分区相对的短写法被考虑过并且否决了：它让同一条路径因为上面的标题不同而含义不同，于是把一行挪到另一个分区就悄悄改掉了它的声称。 啰嗦是有意的——这一列是给「决定该去哪儿看」的人读的。

三条禁令，每一条都是因为它会悄悄烂掉：

  • 不写行号。 src/App.tsx:412 在下一次编辑该文件时就过期了，而路径解析检查抓不到它——文件还在。行号那一级的细节写进「怎么确认」的散文里。
  • 不写计数。 「16 个动作」是一个有半衰期的事实。
  • 不写构建产物。 dist/、target/、coverage/ 下的路径在每一次全新 clone 上都是红的。

门禁

pnpm ledger:check     # 三项机器检查，有发现就退出 1
pnpm ledger:build     # 渲染 docs/feature-ledger.html

ledger:check 问三个问题：每一条路径声称都能解析、每一个状态格都在五值枚举内、app 声明的每一个名字都被写进了某一行。 第三项是关键的那一项——它抓的是「没有人为它写过一行的那个界面」。今天它覆盖 #[tauri::command]、http_server.rs 的路由、menu.rs 的 MENU_* id、pluginConfig.ts 的插件 id、以及 src/stores/ 下的每一个 store。

它不能问一个句子是不是真的。路径能解析，不代表那一行描述的行为还存在。

怎么维护

改变行为的那一次提交，重写它的那一行。 不是后续的清理批次——留到清理批次的状态列，是没有人能信任的状态列。这跟 CLAUDE.md 里对 sequencing doc 的要求是同一条规则。

一次审计 pass 写成一个带日期的小节，追加，不覆盖，并且必须以一段「这次没有关掉什么」结尾。声称自己做了一次全面扫描，正是上一次 pass 存在的意义所要记录的那种过度声称。

Part 4 — 读这张矩阵

mdpro 不该追的

云同步、协作编辑、版本历史。 mdpro 的约束写在 CLAUDE.md 的第一行：本地文件，仅此而已。这三样每一样都要求一个服务端、一个账号体系和一份账单，换来的是一个本地编辑器不需要的东西。

PDF / Word 导出。 被否决过一次，理由是 headless Chromium 的体积（specs/001-mdpro-mvp/spec.md）。导出的 HTML 在浏览器里能打印成 PDF——但这条退路要求用户离开 mdpro，因为 app 自己也没有打印入口（Part 1 的「打印」行，Absent）。PDF 是一个做过的决定，打印不是；把两者当成同一件事，就是用一条立场掩护一个从没被评估过的缺口。

第三方插件市场。 src/plugins/ 这套架构是编辑器内部的，不是对外的扩展点。一旦对外，沙箱、版本兼容和审核就全部变成必须品，而它们没有一个能靠一个人维护。

块编辑器 / 思源那条路。 mdpro 的文件就是 Markdown 文件，不是一棵块树（思源的代价是 .sy JSON，见 Part 3）。这一条不是「还没做」。

缺席是一个立场，不是一个缺口——前提是它被写下来，而写下来正是这份账簿的用处。上面每一条在 Part 3 的矩阵里都不占行；它们在这里。

需要分清的两类缺席

Part 3 的「人人都有而 mdpro 没有」是缺口：对标物几乎都有、mdpro 没有、且没有一个写下来的理由说明为什么不该有。上面这一节是立场。把立场混进缺口表里，会让下一个读这张表的人去修一个已经做过决定的东西；反过来把缺口说成立场，则是更贵的那个方向——它让一件没人想过的事看起来像一件想过的事。上面「打印」那一段就是这条线的示范。

对外该怎么说 mdpro 独家

不要再说「mdpro 有 MCP」。 建账时核到 Bear 2.8 已经有第一方 MCP；2026-09-22 换组后，SiYuan 与 Joplin 也有（Part 3 第三张表的要点 1）。这句话在 2026 年 9 月已经不成立了。

「写进用户此刻正在打字的那个缓冲区」也不再能单独当卖点。 建账时这一格没有对手；换入 VMark 后有了——它的 MCP document.write 落进它自己持有的标签页缓冲区。Bear、SiYuan、Joplin 仍然对着存储层说话，所以这句话对十一个对照组里的十个仍然成立，但对与 mdpro 同构的那一个不成立。产品文案在找到相对 VMark 的差异之前，不应再用「独家」这个词；那个差异要比较两者的 MCP 工具集（mdpro 有 mcp:table_action 等表格工具），本次没有做。

第一顺位缺口

现在的第一顺位缺口是：WYSIWYG 模式下 $…$ 和 [^1] 是字面文本。

理由不是「缺的人最多」。按 Part 3 的三桶分，WYSIWYG 数学整体上落在「有争议」那一桶——十一个对标物里它并不普遍。选它是因为桶的划分不看总数，看谁：在 Typora、MarkText、Zettlr、Bear 这四个直接对标物，外加与 mdpro 同构的 VMark——也就是同样主打「所见即所得地写 Markdown」的那条产品线——上，它是 ●。mdpro 的整个卖点是「Typora 的所见即所得体验」，而在 mdpro 的主要编辑模式里，$…$ 和 [^1] 是字面文本。

今天它们只在 Rust 渲染面上排版，也就是只在导出时——src/services/mathRender.ts 的唯一 import 方是 src/services/exportService.ts，Preview 面板在 stage-2 死代码清理里已经删掉了。这是 Phase 1 明确接受的行为（决策 B3），不是缺陷；但一个被接受的缺席仍然是一个缺席，而这一个正对着产品的那句话。这就是它排在第一顺位的全部理由：它不是最大的洞，它是唯一一个让产品的自我描述不成立的洞。

第一顺位只有一条，但最便宜的一条不是它。 如果要的是「今天就能让矩阵少一个洞」，那是字数统计——十一个对标物无一例外都有，mdpro 零代码，且它不碰渲染管线、不碰插件 registry、不碰任何已做过的决定。把它写在这里，是为了不让它在只盯第一顺位的读法里被丢掉。

这是首次建账，所以这里还没有被划掉的历史。以后关掉一条，就在它上面加删除线、写上是什么关掉的，保留原地，然后在下面写新的一条——任何时刻只有一条。一份给出四色清单的账簿，给不出「下一件事是什么」这一个答案。

最有后果的架构发现，但它不是第一顺位

pluginRegistry.getMilkdownPlugins() 的调用点是零。registry 只治理 CodeMirror；三个 Milkdown 插件能到编辑器里，只是因为 src/components/Editor/MilkdownEditor.tsx 直接 import 了实例本身。后果是每一个 Milkdown 插件在 src/plugins/core/pluginConfig.ts 里的 enabled 开关都是装饰品——setPluginEnabled("image-paste", false) 不会关掉图片粘贴——而且 currentMode 从不会是 "milkdown"，所以没有任何 Milkdown 插件收到过 init() 或 destroy()。

它排在第一顺位缺口之后，因为它今天不改变任何用户看得见的行为。它排在这里而不是被略过，是因为它让每一条关于 Milkdown 插件的声称都无法验证，包括这份账簿里的那些。
