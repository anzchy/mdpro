Plugin System Architecture

mdpro Editor - Proposed Refactoring

Architecture Comparison
Current Architecture
  • Extensions scattered in components/Editor/extensions/
  • No unified plugin interface
  • Hard-coded in Editor.tsx and useMilkdown.ts
  • Features tightly coupled to core
  • No enable/disable mechanism
  • Different patterns for CodeMirror vs Milkdown
Proposed Architecture
  • All features in src/plugins/
  • Standard MdproPlugin interface
  • Central Plugin Registry
  • Features decoupled from core
  • Configuration-based enable/disable
  • Unified patterns across both editors
