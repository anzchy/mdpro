# mdpro — planning documents and progress map

**The spec-kit era is over.** `specs/001-mdpro-mvp` … `specs/008-image-paste` are historical
records of shipped or abandoned work. **Code is authoritative; never implement from `specs/`.**
The MVP contracts in `specs/001-mdpro-mvp/contracts/` are the one exception worth reading, and
only to learn what an IPC command was *originally* meant to do — `src-tauri/src/commands/` is
the truth.

## Where documents live

| Path | Contents | Lifecycle |
|---|---|---|
| `docs/plans/*.md` | Standalone plans and records for one effort | Living until the work ships |
| `docs/plans/20260911-ui-redesign/` | Plan P's per-stage work-item files (`stage-0-inventory.md` … `stage-5-source-font.md`) plus `decisions.md`, `risks.md`, `baseline-protocol.md` | Living |
| `docs/plans/archive/` | Plans whose effort closed | Frozen; do not edit |
| `docs/adr/` | 36 ADRs (`0001`–`0036`) — the **why** behind long-lived constraints, one file per decision | **Survives** plan archival; never edited after Accepted, only superseded |
| `docs/test/` | Dated GUI-acceptance records (one per defect/ADR verified on a real device) | Append-only evidence |
| `docs/guide/` | Reference material CLAUDE.md links out to (architecture, debugging, view-modes, tables, …) | Living |
| `docs/reference/` | Research and competitor/workflow analyses — **not** decisions | Living |
| `docs/architecture/*.html` | Generated architecture views | Generated; never hand-edit |
| `docs/feature-ledger.md` | Inventory of what mdpro has **right now** | Rewritten by the commit that changes behaviour |
| `docs/feature-ledger.html` | Rendered ledger | Generated by `pnpm ledger:build`; never hand-edit |

There is **no `docs/adr/README.md` index.** Find an ADR by filename (`ls docs/adr/`); the
titles are full sentences on purpose. Do not create an index without being asked — an
unmaintained index is worse than `ls`.

## Which document owns which fact

Five documents, five non-overlapping jobs. When two disagree, this order settles it:

1. **`docs/adr/NNNN-*.md`** — the decision. An ADR beats a plan; a plan that contradicts an
   accepted ADR is corrected, not obeyed. To change your mind, write a **new** ADR that
   supersedes the old one; both stay in the tree.
2. **`docs/plans/20260911-plan-ui-redesign.md` (Plan P)** and
   **`docs/plans/20260912-plan-markdown-source-consolidation.md` (Plan M)** — acceptance
   criteria. These are where a work item's definition of done lives.
3. **`docs/plans/20260912-frontend-backend-sequencing-order.md`** — **the sole definition site
   for execution order and status**, and nothing else. It carries order + status only; when it
   and a plan disagree on acceptance, **the plan wins and the sequencing doc is corrected**.
4. **`docs/feature-ledger.md`** — present-tense capability state, not plan state.
5. **`CHANGELOG.md`** — when it shipped.

**ADRs are not plans.** A plan compares options and tracks execution; an ADR records the
outcome that must outlive the plan. Decisions worth interrupting a human for (anything that
reached `AskUserQuestion`) are ADR-worthy. Record the **costs**, not just the benefits — an
ADR whose Consequences section lists only upsides is advocacy, not a record.

Decisions for the in-flight redesign still live inline in `docs/plans/` (E26, E29, E39, the
`export_html` non-deletion). **Do not backfill them wholesale.** Promote one when it is next
disputed, superseded, or built on.

## Status vocabulary — a closed enum

The sequencing doc's legend (`:16`) is fixed. Do not invent a marker:

`✅ 已完成并验证` ｜ `🔄 部分完成` ｜ `⬜ 未开始` ｜ `⏭️ 已改期到另一个 PR` ｜ `⛔ 常驻约束（非任务）`

**`✅ 已完成并验证` means its own gates ran green — not that the code is written.** Updating
the status is part of finishing the work item: the same commit updates the row, the SHA, and
anything the work proved wrong. A status column refreshed in a later cleanup pass is a status
column nobody can trust.

The feature ledger has its own closed enum of five words — `Shipped` / `Partial` / `Stub` /
`Absent` / `Unknown`. `Shipped (export only)` is a gate failure, not a nuance; nuance goes in
the 怎么确认 column, and `Partial` **must** carry a literal `限制：`.

  work item *and* every phase: build / test / cargo test / file-set overreach / no new deps /

## Branches

mdpro does **not** allocate numbered branches. Since 2026-10-12 `master` is the only permanent
branch ([ADR-0083](../../../docs/adr/0083-master-is-the-single-integration-trunk.md)):

**Every work item is a short-lived `<type>/<id>-<slug>` branch (`fix/…`, `feat/…`, `docs/…`,
`chore/…`) off `master` in its own worktree, rebased onto `master` before handoff, and landed
only by the delegator with `git merge --ff-only`. Never commit to `master` directly, never land by
merge commit.**

`release/x.y` exists only for a hotfix to a released version: cut from the tag when needed, fixed
by `cherry-pick -x` from `master`, never merged back. `frontend-backend-redesign`, which carried
the UI-redesign × Markdown-consolidation effort until 2026-10-12, is frozen.
Plans consumed by the autonomous small-feature loop have their own naming contract —
`docs/plans/<YYYYMMDD>-feat-<slug>.md` with a `## Acceptance Criteria` checklist the verifier
parses; see `docs/plans/README.md`.

The gate commands are `pnpm test:run`, `pnpm build`, `pnpm typecheck:tests`,
`cd src-tauri && cargo test`, `pnpm coverage`, and `pnpm ledger:check` — see the `release-gate`

**there is no `main` branch** — the default branch is `master`. Any artifact naming either is
stale; treat it as a bug in that artifact, not as a command to run.

## What mdpro has today

Don't infer it from plans — read `docs/feature-ledger.md`, and run `pnpm ledger:check` before
committing a behaviour change. The gate answers three questions: every path claim resolves,
every state cell is in the five-word enum, and every declared app surface
(`#[tauri::command]`, `http_server.rs` routes, `menu.rs` `MENU_*` ids, `pluginConfig.ts`
plugin ids, `src/stores/`) appears in some row. **It cannot tell you a sentence is still
true** — a path that resolves says nothing about whether the behaviour still exists.
