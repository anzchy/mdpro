## Unit: `src/utils/largeDocumentGuard.ts#decideLargeDocumentGuard`

**Law**: This unit has **five** laws, and they are the whole point of the change.

- **L1 — Totality of the view-mode gate.** For all `content`, `viewMode !== "wysiwyg"` ⇒ `{action:"allow"}`, and `content` is never read. (Covered S4 by G2'/G18'a.)
- **L2 — Conservation / additivity of the score over `\n`-aligned concatenation.** For `\n`-terminated `A`: `score(A ⧺ B) = score(A) + score(B)`. Exactly, not approximately: `newlines` and `pipes` are additive by construction, and because `A` ends in `\n` the segment boundary coincides with a line boundary, so `rowStarts` is additive too. **This is ADR-0016 Decision 3 expressed as a law** — a per-table-maximum accounting (ADR-0006), a scan that early-exits, and a scan that only reads a prefix all violate it. (Covered S5 by N4.)
- **L3 — Monotonicity of the decision in the score, and non-negativity.** Each line contributes `pipes_in_line − [line is a row start] ≥ 0`, because a row start implies at least one pipe; therefore `score ≥ newlines ≥ 0` and `score` is a non-negative integer. Consequently `action === "degrade-to-source" ⟺ score > 25_000` — a total order with one cut point, and the decision is monotone in the score.
  **Scope of the append clause, narrowed deliberately (revision 2).** What this matrix asserts is (i) monotonicity of the *decision* along the realised ascending score ladder of `\n`-only documents (G6'/G7'), and (ii) exact additivity over `\n`-aligned concatenation where both fragments are independently above threshold (N4). It does **not** assert general append-monotonicity, `score(A ⧺ B) ≥ score(A)` for arbitrary `A` and `B`, and **no case is added for it** — see Deferred 12. Revision 1's wording ("score is non-decreasing under append") claimed more than the matrix covers; a wording that outruns its cases is the same failure mode as a false coverage claim, just quieter.
- **L4 — CRLF metamorphic invariance.** For any `\r`-free document `d`, `decide(crlf(d))` deep-equals `decide(d)`, where `crlf` maps `\n → \r\n`. The `\r` adds no newline and no pipe, and it can only ever sit at end-of-line in well-formed CRLF, so it never displaces a line's first non-whitespace character. (Covered S6 by N5.)
- **L5 — Purity / idempotence / freshness.** Repeated calls on the same input return equal decisions; the input is never mutated; two degrade decisions are distinct objects. (Covered S5 by G17'/G22'.)

**Explicitly NOT a law, recorded so nobody tests for it**: the score is *not* byte-monotone, *not* a count of anything the editor builds, and *not* correct for ragged tables, table geometry, or inline structure. ADR-0016 Consequences states all four are unmeasured or knowingly wrong. Any test asserting a ragged table is counted correctly, that 10,000×4 and 40×1,000 differ, or that a 24,000-element 5 MB document is safe **contradicts the ADR and must be rejected in review** (plan risk 9).

### Shared harnesses (define once, at the top of the rewritten file)

```
AT_THRESHOLD = "\n".repeat(25_000)     // score exactly 25_000 — allows (pinned by G4')
atMargin(fragment) -> decideLargeDocumentGuard({ viewMode: "wysiwyg", content: AT_THRESHOLD + fragment })
```

`atMargin` is the measurement instrument for N1. It is deliberately **not** a large pad plus a subtraction: placing every fragment at the tightest possible margin makes each row simultaneously (a) an exact-score assertion via `elements === 25_000 + s` and (b) an allow/degrade discrimination at distance 1 from the cut point, so a score-0 fragment and a score-1 fragment produce *different actions*, not merely different numbers. The harness must carry two self-checks — `atMargin("")` is `{action:"allow"}` and `atMargin("\n")` is a degrade reporting `25_001` — so a drifted `AT_THRESHOLD` fails loudly in the harness rather than silently re-basing every row.

Because `AT_THRESHOLD` ends in `\n`, every fragment passed to `atMargin` begins at a **fresh line start**. That is load-bearing for N1 rows 3-24 and for N13(b) and N17, and must be stated in the harness comment.

**Constraint G0 honoured**: no property library. `fast-check` is not in `package.json` and must not be added. Every S4-S6 case below uses a hand-rolled explicit case table plus a cross product — named as such in each case.

### C. The score arithmetic — the line-start state machine

#### Case N1: the fragment score table at the margin (the branch-coverage workhorse)
- **Category**: boundary + property
- **Lane**: unit
- **Spec level**: **S4** — a partition of the scanner's input space by *state-machine transition*, not a list of examples. Every row names the transition it exercises; together the rows cover all of: document start treated as a line start, line start after `\n`, whitespace skip (space), whitespace skip (tab), unbounded whitespace skip, line-start state left by a non-whitespace non-pipe character, pipe at line start, pipe not at line start, **a row start whose line does NOT close with a pipe (rows 23, 24 — added in revision 2; without them the partition omits an entire transition class and the S4 claim is not honest)**, empty line, all-whitespace line, EOF mid-line, EOF immediately after `\n`.

- **Escaping convention — state it once, above the table, in the test file too.** Every fragment below is written **as a JavaScript string literal, exactly as it must be typed in the test source**, and the table is rendered in a fenced block precisely so that Markdown's own pipe-escaping cannot reintroduce ambiguity. So `"\n"` is one newline, `"\t"` one tab, `"\r"` one carriage return, `"\u00A0"` one NBSP, and a bare `|` inside a literal is just a pipe (JS requires no escape for it). **Nothing in this table uses Markdown-style escaping.** This convention is load-bearing and is why revision 1's row 15 had to be fixed: written `"\|---\|---\|"` it read one way as Markdown escaping (`|---|---|`, 3 pipes − 1 row start = **2**, the delimiter-row over-count as labelled) and another way as a JS literal (three backslash-pipe pairs, **not** row starts, 3 pipes − 0 = **3**, silently becoming an escaped-pipe test with a wrong expectation). The number *and* the rule under test changed with the reading.

- **Input**: `atMargin(fragment)` for each row (expected fragment score `s`; `AT_THRESHOLD` contributes exactly 25,000, and its trailing `\n` guarantees each fragment starts at a fresh line start):

```text
  #  fragment (JS string literal, verbatim)   s   transition pinned
  1  ""                                       0   EOF immediately after "\n"
  2  "\n"                                     1   empty line
  3  "x"                                      0   line-start state left by a non-ws non-pipe char; EOF mid-line
  4  "|"                                      0   pipe at line start => +1 pipe, -1 row start
  5  "||"                                     1   one row start per LINE, not per pipe
  6  "x|"                                     1   pipe after the line-start state was left => no subtraction
  7  " |"                                     0   single leading space skipped
  8  "\t|"                                    0   leading tab skipped (tab IS whitespace)
  9  "       |"   (7 spaces, then a pipe)     0   UNBOUNDED skip - kills a GFM 3-space implementation
 10  "\u00A0|"                                1   NBSP is NOT whitespace - kills trimStart() / /\s/
 11  "\r|"                                    1   lone CR is not whitespace and not a newline
 12  "\u{1F600}|"                             1   astral char does not perturb the scan
 13  "| a | b |"                              2   3 pipes - 1 row start
 14  "a | b"                                  1   omitted outer pipes - ADR-accepted UNDER-count
 15  "|---|---|"                              2   delimiter row - ADR-accepted OVER-count (3 pipes - 1 row start)
 16  "| a | b |\n"                            3   one full LF table row
 17  "   | a | b |\n"                         3   indented table row
 18  "\t| a | b |\n"                          3   tab-indented table row
 19  "| a | b |\r\n"                          3   CRLF table row scores as LF
 20  "```\na|b\n```\n"                        4   fenced code - ADR-accepted OVER-count
 21  "\n|"                                    1   line start re-armed after "\n"
 22  " \n |"                                  1   all-whitespace line, then indented pipe
 23  "| a | b\n"      (NEW, rev 2)            2   ROW START WITHOUT A CLOSING PIPE: 1 newline + 2 pipes - 1 row start
 24  "| a | b"        (NEW, rev 2)            1   same, unterminated at EOF: 2 pipes - 1 row start
```

- **Expected output**: for `s === 0`, `{ action: "allow" }`; for `s >= 1`, `{ action: "degrade-to-source", message: <full literal>, elements: 25_000 + s }`
- **Observable side effect**: none
- **Assertion strategy**: Level 1 — whole-object `toEqual` per row, collected **unwrapped**, asserted after the loop with a parallel label array carrying the row number and the transition name. Plus **three** invariant assertions over the collected set: every reported `elements` satisfies `Number.isInteger` and `>= 25_000` (L3 non-negativity — the honest successor to the retired G8/G9), and **`new Set(rows.map(r => r.fragment)).size === rows.length`** — the fragments are pairwise distinct. The third one exists because two rows that collide assert different scores for the same input, which is a self-contradictory table that fails in a way nobody can localise; it is the structural guard behind the escaping convention, and it holds for every row, not just the ones written with an escape today.
- **Mock boundary**: none — real implementation
- **Refactor that would break this**: any change to the whitespace set, the row-start rule, the pipe accounting, or the treatment of the document's first line.
  - Rows 7-11 are the four that kill four distinct plausible-but-wrong implementations (`trimStart`, `/\s/`, a 3-space GFM bound, per-pipe subtraction). Row 10's failure is what enforces the ADR's constant-auxiliary-space invariant *behaviourally*: `trimStart()` allocates a string per line, and rejecting NBSP is the observable consequence of not calling it.
  - **Rows 23 and 24 are the two that kill the "delimited on both sides" implementation** — the one wrong implementation that survived revision 1 of this matrix whole:
    ```
    at each line: firstNonWs = first char code not SPACE/TAB
                  lastNonWs  = last  char code not SPACE/TAB/CR
    on line end:  if (firstNonWs === PIPE && lastNonWs === PIPE) rowStarts++
    score = newlines + pipes - rowStarts
    ```
    It is single-pass, allocation-free, adds no `<=` and no numeric literal, so **C12 and C8b' do not see it**. It ships a ~1-per-row over-count on every GFM table written `| a | b` without the trailing pipe — the mirror image of the under-count the ADR knowingly accepts at row 14 / N11, but *unrecorded*, which is what makes it a defect rather than a cost. It reports 25,003 on row 23 and 25,002 on row 24 against the correct 25,002 / 25,001, and fails both. **The comment on these two rows must say that the rule is "first non-whitespace character is `|`", full stop — a closing pipe is neither required nor consulted (WI-1 answer (2)), and GFM makes outer pipes optional, so requiring one is wrong on real documents, not merely unspecified.**
  - Row 15's reading is now fixed by the escaping convention above; it is the delimiter-row over-count and nothing else.
- **Note on row 12**: recorded honestly — **this row kills nothing known.** Code-unit versus code-point iteration cannot change the score, because no surrogate half can equal 10, 124, 32, or 9. It is kept as a defensive regression guard (the D6.1 corpus contains emoji; a throw or a mis-index here would be a real bug), not as a discriminator, and it is labelled so in the file.
- **Cross-reference**: the transition "first non-whitespace character is a backslash, therefore not a row start" lives in **N17** rather than here, because it is a characterization of an accepted defect (S1) and folding it into this S4 partition would read as endorsing the defect. N1's comment must point at N17 so the partition's boundary is visible.

- **Input**: pair — (a) `{ viewMode: "wysiwyg", content: "|".repeat(30_000) }`; (b) `{ viewMode: "wysiwyg", content: "x" + "|".repeat(30_000) }`

### D. The laws

#### Case N4: L2 — conservation, the score is additive over `\n`-aligned concatenation
- **Category**: property
- **Lane**: unit
- **Spec level**: **S5** — an invariant across composition, over a generated (cross-product) input domain. Hand-rolled generator; G0 forbids `fast-check`.
- **Input**: four `\n`-terminated fragments, **each independently above the threshold so its own `elements` is directly observable** (this independence is what kills early exit without relying on the property under test):
  - `F1 = "\n".repeat(26_000)` → 26,000
  - `F2 = "| a | b | c | d |\n".repeat(6_000)` → 30,000
  - `F3 = "   | a | b |\n".repeat(9_000)` → 27,000
  - `F4 = "| a | b |\r\n".repeat(9_000)` → 27,000
  All 16 ordered pairs `(A, B)`.
- **Expected output**: for every pair, `elements(A ⧺ B) === elements(A) + elements(B)`, where all three numbers are read from three real calls. No expected constants are hard-coded on the right-hand side — the relation is the assertion.
- **Observable side effect**: none
- **Assertion strategy**: Level 1 — `expect(elementsOf(A + B), label).toBe(elementsOf(A) + elementsOf(B))` for all 16 pairs, collected unwrapped and asserted after the loop. A small helper narrows the union and throws on an unexpected `allow`, so a wrong `allow` fails loudly rather than being skipped.
- **Mock boundary**: none — real implementation
- **Refactor that would break this**: **early exit on threshold crossing** (the concatenation stops at the same character as `A` alone, so `elements(A⧺B) === elements(A)`); **ADR-0006's per-table-maximum accounting** (the concatenation of two tables reports the larger, not the sum); any prefix-limited scan; any per-chunk state reset. This is the single strongest case in the matrix and the behavioural encoding of ADR-0016 Decision 3 and of WI-1 answer (3)'s "no early exit".
- **Scope note (L3, revision 2)**: all four fragments are `\n`-aligned and above threshold. This case therefore does **not** generalise to arbitrary append; the narrowing is deliberate and is recorded in L3 and Deferred 12 rather than papered over by a broader claim in the case name.

#### Case N6: L2 applied — whole-document total, not the largest single table
- **Category**: property (the named consequence of L2)
- **Lane**: unit
- **Spec level**: **S5** — a state/composition invariant instantiated on the exact shape that distinguishes ADR-0016 from ADR-0006
- **Input**: `TABLE = "| a | b | c | d |\n".repeat(600)` (score 3,000 — the largest *single* table, 2,400 rendered cells); `DOC = Array.from({length: 10}, () => TABLE).join("\n")` (nine joining `\n`, score 30,009)
- **Expected output**: `decide({viewMode:"wysiwyg", content: TABLE})` is `{action:"allow"}`; `decide({viewMode:"wysiwyg", content: DOC})` is `{action:"degrade-to-source", message:<full literal>, elements: 30_009}`
- **Observable side effect**: none
- **Assertion strategy**: Level 1 — whole-object `toEqual` on both halves. The **pair** is the case: allow-then-degrade is what refutes the superseded accounting; either half alone proves nothing.
- **Mock boundary**: none — real implementation
- **Refactor that would break this**: reverting to "cells in the largest single table" (allows `DOC` at 2,400 cells); any per-table maximum; any scan that resets its accumulator at a blank line.

#### Case N5: L4 — CRLF metamorphic invariance
- **Category**: property
- **Lane**: unit
- **Spec level**: **S6** — a metamorphic relation: `decide(crlf(d))` deep-equals `decide(d)` for all `\r`-free `d`, with no independent oracle for either side
- **Input**: a hand-rolled table of eight `\r`-free documents spanning both sides of the cut point: `""`, `"\n"`, `AT_THRESHOLD`, `AT_THRESHOLD + "\n"`, `"| a | b |\n".repeat(10_000)`, `"   | a | b |\n".repeat(9_000)`, `"a | b\n".repeat(20_000)`, `"- item\n".repeat(32_657)`. CRLF built as **`d.split("\n").join("\r\n")`** — *not* `replaceAll`, which is ES2021 and fails TS2550 under `tsconfig.json:5` (`lib: ES2020`).
- **Expected output**: for each document, `decide(crlf(d))` deep-equals `decide(d)` — including `elements` on the degrade rows
- **Observable side effect**: none
- **Assertion strategy**: Level 1 — whole-object `toEqual` between the two real results, per row, labelled. Both sides are real calls; nothing is hard-coded, so this case cannot be satisfied by a constant.
- **Mock boundary**: none — real implementation
- **Refactor that would break this**: treating `\r` as a newline (doubles every count); treating `\r` as whitespace in the line-start skip (changes nothing here, but see N13 which pins the opposite direction); a scanner that reads two characters at a time and desynchronises on the two-byte terminator. Grounded in reality, not hypothesis: the D6.1 perf corpus ships `normal-prose.wysiwyg.crlf.md`.

#### Case N3: byte-length invariance — the direct refutation of the byte predicate
- **Category**: property
- **Lane**: unit
- **Spec level**: **S4** — quantified over a generated filler-length domain, holding the score constant. This is the successor to the retired G16 ("with a non-null fileSize the content is irrelevant"), inverted: content is now the only thing that matters, and *volume* is the thing that must not.
- **Input**: for each `fillerLen` in `[0, 1, 10, 1_000, 60_000]`, the document `("x".repeat(fillerLen) + "\n").repeat(10)` — score 10 in every case, byte length spanning 10 B to ~600 KB. And a second family above the cut point: for each `fillerLen` in `[0, 1, 100]`, `("x".repeat(fillerLen) + "\n").repeat(30_000)` — score 30,000 in every case, byte length spanning 30 KB to ~3 MB.
- **Expected output**: within each family every decision is **deep-equal to every other**: family 1 all `{action:"allow"}`; family 2 all `{action:"degrade-to-source", message:<full literal>, elements: 30_000}`
- **Observable side effect**: none
- **Assertion strategy**: Level 1 — per-row `toEqual` against the family's expected object, plus `expect(new Set(results.map(r => JSON.stringify(r))).size).toBe(1)` per family, which states the invariance directly rather than inferring it
- **Mock boundary**: none — real implementation
- **Refactor that would break this**: any residual byte term (`TextEncoder`, `content.length`, a `Math.max(score, bytes/K)` hybrid). Family 1's 600 KB member is the one the *old* predicate degraded; a partial revert fails here first.

#### Case G17': L5 — purity, idempotence, and no input mutation
- **Category**: determinism
- **Lane**: unit
- **Spec level**: **S5** — idempotence and non-mutation across repeated invocations, over a small input table
- **Input**: four frozen inputs: `{viewMode:"source", content:"| a |\n".repeat(30_000)}`, `{viewMode:"source", content:""}`, `{viewMode:"wysiwyg", content:"x"}`, `{viewMode:"wysiwyg", content:"\n".repeat(25_001)}`. Each `structuredClone`d for a snapshot, then `Object.freeze`d.
- **Expected output**: the call does not throw; `first` deep-equals `second`; the input deep-equals its snapshot; `input.content` is reference-identical (`toBe`) to the snapshot's
- **Observable side effect**: **Level 2 side-effect verification on the caller-supplied object** — the assertion is that nothing changed. ES modules are strict mode, so a write to a frozen property throws a `TypeError` rather than no-opping, which makes `not.toThrow()` a real assertion rather than decoration. Carried forward verbatim from the existing G17 rationale.
- **Assertion strategy**: Level 1 (equality of the two decisions) + Level 2 (the frozen-input observation)
- **Mock boundary**: none — real implementation
- **Refactor that would break this**: writing a normalised copy back onto the input; a memo stored on the input object; any in-place mutation of `content`.

#### Case G22': L5 — a returned degrade decision is not invalidated by the next call
- **Category**: state
- **Lane**: unit
- **Spec level**: **S5** — an invariant across a state transition (call N does not retroactively change the value returned by call N−1)
- **Input**: `first = decide({viewMode:"wysiwyg", content:"\n".repeat(25_001)})`, then `second = decide({viewMode:"wysiwyg", content:"\n".repeat(57_190)})`
- **Expected output**: asserted **after both calls**: `first` deep-equals `{action:"degrade-to-source", message:<full literal>, elements:25_001}`; `second` deep-equals the same shape with `elements:57_190`; `expect(first).not.toBe(second)`
- **Observable side effect**: none
- **Assertion strategy**: Level 1 — the **ordering is the case**. Asserting on `first` before the second call degenerates this into G5' and lets a hoisted, per-call-mutated singleton pass.
- **Mock boundary**: none — real implementation
- **Refactor that would break this**: a module-scope reused degrade object. Scope limit carried forward verbatim: this applies only to two *degrade* decisions — a shared frozen ALLOW singleton remains a legitimate implementation choice, which is why no identity claim is made on the allow arm anywhere in the file.

#### Case G18': `content` is read once, and never in source mode
- **Category**: guard
- **Lane**: unit
- **Spec level**: **S2** — the two sides of the gate partition, plus a positive control
- **Input**: a plain object literal inhabiting `LargeDocumentGuardInput` with a counting getter on `content` (a getter on an object the test constructs is **not a mock**: it is a legal inhabitant of the interface returning the real value). Arms: (a) `{viewMode:"source", get content(){...}}`; (b) positive control `{viewMode:"wysiwyg", get content(){...}}` returning `"\n".repeat(25_001)`.
- **Expected output**: (a) `{action:"allow"}` **and** `reads === 0`; (b) the exact degrade decision **and** `reads` is exactly 1
- **Observable side effect**: **Level 2** — the read counter on the caller-supplied object is an observable side effect of the call
- **Assertion strategy**: Level 2 (`expect(state.reads, "source mode must not read content").toBe(0)`) + Level 1 on the returned decision. Both, in both arms.
- **Mock boundary**: none — real implementation
- **Refactor that would break this**: moving the view-mode gate below the scan; reading `input.content` twice (e.g. once for newlines and once for pipes, which is the shape the ADR's one-forward-pass invariant forbids). **Arm (b)'s exact-1 is a strengthening over the old G18, which asserted `toBeGreaterThanOrEqual(1)`.** Old arm (b) — "a present `fileSize` must not read content" — is **retired by construction**; `fileSize` no longer exists.
- **Honest limit, to be stated in the file**: `reads === 1` proves the *property* is read once. It does **not** prove the scan is single-pass — `input.content.split("\n")` also reads the property once. The one-pass / constant-space invariants are enforced only by C12, a source-text case. Said plainly rather than implied.

### E. ADR-accepted costs — characterization, recorded not endorsed

Each of the **five** cases below exists to **record** behaviour ADR-0016 Consequences deliberately accepts. Each must carry a comment saying so, with the ADR line reference, so a future reader does not "fix" the predicate to make it pass differently (plan risk 9). Rows 14, 15 and 20 of N1 already assert three of these scores at the margin; the cases below re-state them as *named, labelled* cases because the label is the artefact, and add the documents N1 cannot express.

**Revision 2 note.** ADR-0016's over-count family has three members: literal pipes in prose / fenced code, the delimiter row, and — the one revision 1 missed — pipes that a Markdown *parser* would not treat as cell separators at all: an **escaped** `\|` and a pipe inside an **inline-code span**. The first two had tripwires (N10 for the fence, N12 for the inline-density counter). The third had none, and no case in revision 1 contained a backslash or a backtick-delimited span at all, so a one-character-lookback scan that skips `\|` — single-pass, constant-space, no tokenizer, invisible to C12 and C8b' — would have shipped a parsing rule under Decision 1's frozen invariants with a fully green suite. **N17 closes that asymmetry.**

#### Case N10: accepted over-count — a fenced code block and a GFM delimiter row both contribute cells
- **Category**: determinism (characterization)
- **Lane**: unit
- **Spec level**: **S1** — two documents, two recorded scores. Deliberately not generalised: generalising an accepted defect would read as endorsing it.
- **Input** *(stated once; revision 1 contained a mid-draft self-correction here that would have made an implementer write a test failing against a correct implementation)*:
  - (a) `"```\na|b\n```\n".repeat(7_000)` — per block: 3 newlines + 1 pipe − 0 row starts = **4**; 4 × 7,000 = **28,000**
  - (b) `"| a | b |\n|---|---|\n| 1 | 2 |\n".repeat(3_000)` — per table: 3 newlines + 9 pipes − 3 row starts = **9**; 9 × 3,000 = **27,000**
  **`.repeat(7_000)`, not `5_000`.** At 5,000 the score is 20,000, which is *below* the 25,000 threshold, so the document allows — and a fence-tracking implementation scores it 15,000 and also allows. Expecting `allow` there would leave the case discriminating nothing while its label still claimed a fenced-code tripwire: the tripwire silently deleted, the claim left standing. The whole point of this case is that it must **degrade**, and degrade at a number a fence-tracking implementation cannot produce (15,000 → allow).
- **Expected output**: (a) `{action:"degrade-to-source", message:<full literal>, elements: 28_000}`; (b) `{action:"degrade-to-source", message:<full literal>, elements: 27_000}`
- **Observable side effect**: none
- **Assertion strategy**: Level 1 — whole-object `toEqual` on both, with a comment recording that the honest rendered count for document (b) is 3 newlines + 4 cells = 7 per table (21,000), and that the 6,000-element excess is ADR-0016's knowingly-accepted over-count
- **Mock boundary**: none — real implementation
- **Refactor that would break this**: adding fence tracking or delimiter-row detection — both of which would be *Markdown parsing*, which ADR-0016 Decision 1 freezes out. This case is the tripwire on that invariant.
- **Deliberate redundancy, recorded**: **N1 row 20 covers the same fenced-code attack** at the margin (fragment score 4). That overlap is intentional, not accidental — N1 row 20 gives the branch-coverage and the exact-arithmetic reading; N10(a) gives the *named, labelled* case a future reader will find when they go looking for "why does a code fence count". Neither is redundant with the other's purpose, and neither should be deleted on the grounds that the other exists.

#### Case N11: accepted under-count — omitted outer pipes score one cell, not two
- **Category**: determinism (characterization)
- **Lane**: unit
- **Spec level**: **S1**
- **Input**: `"a | b\n".repeat(20_000)` (per row: 1 newline + 1 pipe − 0 row starts = 2)
- **Expected output**: `{action:"degrade-to-source", message:<full literal>, elements: 40_000}`
- **Observable side effect**: none
- **Assertion strategy**: Level 1, with a comment naming the accepted under-count (2 rendered cells per row counted as 1)
- **Mock boundary**: none — real implementation
- **Refactor that would break this**: inferring column counts from a header row — again, parsing.
- **Pairing note (revision 2)**: N1 rows 23/24 pin the *mirror* of this cost. GFM makes outer pipes optional on both ends; N11 records that dropping the **leading** pipe loses a cell (accepted, recorded), and N1 rows 23/24 record that dropping the **trailing** pipe must still produce a row start (required, not optional). An implementation that demands a closing pipe converts the second into an unrecorded over-count. State the pairing in both comments.

#### Case N12: the accepted blind spot — 20,000 inline links in one paragraph are allowed
- **Category**: determinism (characterization)
- **Lane**: unit
- **Spec level**: **S1** — ADR-0016's sharpest recorded hole, pinned at exactly one point
- **Input**: `{ viewMode: "wysiwyg", content: "[asset](./a/b.png) ".repeat(20_000) }` — one paragraph, no newline, no pipe
- **Expected output**: `{ action: "allow" }`, and `Object.keys(result)` is exactly `["action"]`
- **Observable side effect**: none
- **Assertion strategy**: Level 1
- **Mock boundary**: none — real implementation
- **Refactor that would break this**: **adding a `[` counter.** That is exactly the change ADR-0016's Deliberation note **declines** — shipping an unmeasured counter is the error the ADR exists to correct. The comment must say so in capital letters: this case going red means someone added an inline-density proxy, which requires a new ADR, not a green suite.
- **Number note, revision 2 — do NOT "correct" this case to match the ADR's figure.** ADR-0016 Consequences says the 20,000-link document "scores 1"; this case's document scores **0**. Both are right about their own document: the ADR's prose assumes a paragraph terminated by one newline (`0 pipes + 1 newline`), and this input has no trailing newline (`"[asset](./a/b.png) "` ends in a space). The discrepancy is one trailing `\n`, not a disagreement about the predicate. Written into the comment so a future reader reconciling the case against the ADR does not "fix" the expectation to 1 — which, with this input, would make the case red against a correct implementation.

#### Case N13: lone `\r` line endings score zero newlines and suppress the row-start subtraction
- **Category**: determinism (characterization)
- **Lane**: unit
- **Spec level**: **S1**
- **Input**: (a) `{viewMode:"wysiwyg", content: "\r".repeat(30_000)}`; (b) `atMargin("\r| a | b |")`
- **Expected output**: (a) `{action:"allow"}` — zero newlines, zero pipes, score 0; (b) degrade with `elements: 25_003` (3 pipes, no row start, because the leading `\r` is neither whitespace nor a newline under WI-1 answer (2))
- **Observable side effect**: none
- **Assertion strategy**: Level 1
- **Mock boundary**: none — real implementation
- **Refactor that would break this**: adding `\r` to the newline set or the whitespace set. **This is the deliberate counterpart to N5**: CRLF must be invariant (because `\r` sits at end-of-line there), and classic-Mac lone `\r` must not be normalised (because normalising it is a step toward parsing). The two cases together pin the exact boundary of the `\r` rule; either alone is ambiguous.

#### Case N17 (NEW, revision 2): accepted over-count — an escaped `\|` and an inline-code pipe both still count, and neither opens a row
- **Category**: determinism (characterization)
- **Lane**: unit
- **Spec level**: **S1** — characterization of a deliberately accepted defect, pinned at exactly two points. Deliberately **not** generalised, for the same reason as N10/N11/N12: generalising an accepted defect reads as endorsing it, and the honest claim here is "this is what the counts-only scan does", not "this is what a table looks like".
- **Input** — same JS-string-literal convention as N1; both measured through `atMargin`, so both sit one element from the cut point and an off-by-one changes the *action*, not just the number:

```text
  #  fragment (JS string literal, verbatim)   s   transition pinned
  1  "\\| a\n"        (backslash, pipe, …)    2   escaped pipe STILL COUNTS as a cell (1 newline + 1 pipe);
                                                  and the line is NOT a row start, because the first
                                                  non-whitespace character is "\", not "|"  -> 0 subtractions
  2  "`a|b`\n"        (backtick a pipe b …)   2   inline-code pipe STILL COUNTS - there is no span tracking
                                                  (1 newline + 1 pipe - 0 row starts)
```

- **Expected output**: both rows degrade with exactly `{action:"degrade-to-source", message:<full literal>, elements: 25_002}`
- **Observable side effect**: none
- **Assertion strategy**: Level 1 — whole-object `toEqual` per row, collected unwrapped, asserted after the loop with a parallel label array, exactly as N1 does
- **Mock boundary**: none — real implementation
- **Refactor that would break this**: **a one-character lookback that skips `\|`** ("escaped pipes aren't cells"), or **backtick-span tracking** that suppresses pipes inside inline code. Both are single-pass and constant-space, so **C12 cannot see them** and **C8b' cannot see them** (neither adds a numeric literal or a `<=`). Both are nevertheless **Markdown parsing rules**, which ADR-0016 Decision 1 freezes out — and both were invisible to revision 1 of this matrix, which contained no backslash and no backtick-delimited span anywhere.
- **The comment must say, in the same register as N12's**: *this case going red means someone has added a parsing rule to a predicate whose frozen invariant is "no Markdown parsing, no tokenizer". That is a change to the invariants, not to the arithmetic, and ADR-0016 Decision 1 says changing the invariants **requires a new ADR**. A green suite is not the remedy.*
- **Second question this row closes**: row 1 is the only case anywhere in the matrix that pins **whether `\|` at column 0 is a row start**. Under WI-1 answer (2) it is **not** — the rule is "first non-whitespace character is `|`", and the first non-whitespace character here is `\`. Revision 1 said nothing either way, so an implementation could have gone either direction unnoticed.
- **Relation to N1**: these two rows could have lived in N1's table, and the arithmetic would be identical. They are kept separate because N1 carries an **S4** partition claim and these carry an **S1** characterization claim; mixing them would either inflate N17's claim or launder N10/N11/N12's accepted-defect labelling into a "the scanner is correct here" reading. N1's comment cross-references this case so the partition's boundary is explicit.

### G. Evidence anchors — the ADR's empirical claims

#### Case N15: the headline inversion — a 600 KB single line is allowed
- **Category**: success
