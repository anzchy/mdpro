Settings › Keyboard Shortcuts

Where the plan leaves a choice open (the same in all three variants unless noted):
  1. Quote on macOS has no key (open question 1, K3): drawn keyless until the M2 spike decides ⌥⌘Q.
  2. F6 alone for Toggle Source Mode (open question 2): ⌘/ / Ctrl+/ is not drawn as a second key. If it is kept, macOS can show only one key per item, so the second key would be Settings-only.
  3. (W) and (S) items look exactly like "not available" in a native menu. macOS and Win32 have one disabled style. Only b and c can tell them apart, by hiding the key or moving the item.
  4. Windows, WYSIWYG: Find is greyed while Ctrl+F works (§ 5.2, open question 7): WebView2's find bar opens. The menu says "unavailable" and the key says otherwise.
  5. View order differs by platform: § 5.1 puts Source, WYSIWYG, then Toggle Source Mode; § 5.2 puts Toggle Source Mode first. Drawn as written.
  6. The menu is "Themes" in § 5.1 / 5.2 (today: "Theme"). Drawn as written.
  7. Settings has no row for Export HTML, Highlight, Undo/Redo, Exit or Settings itself today. M7 adds the nine missing contract fields, but the plan doesn't say which group each joins. Drawn here: Export HTML in File, Highlight in Format, Exit in File (Windows), Undo/Redo fixed in Edit.
  8. Jump to Top / Bottom become "system" rows (§ 5.3.2) with no menu item. Drawn as a fixed, non-editable key.
  9. Not drawn by the plan, inserted by macOS: the Help search field, the Window menu's list of windows, and View › Enter Full Screen. They are shown here so the menus look as they will.
  10. D7 (D255 builds what it can) will shrink the "n/a" set. These mock-ups use § 5.1's set as it stands.
